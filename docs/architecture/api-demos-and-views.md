# API: walkthroughs, reviews, DDD runs, shareouts, storyboards and dynamic views

The rules for the demo and review surfaces: walkthroughs, narrative reviews, DDD runs, shareouts, storyboards, dynamic views and issues. Part of the [api surface](api-surface.md) topic. Routes, fields and gates are in each router file and the OpenAPI schema; this page holds what they do not say.

## Issues (`apps/issues`)
`apps/issues/api.py`: `canopy.origin` records (GitHub issue provenance). `(repo, number)` is globally unique, so a record in a workspace the caller is not in is 404 (never overwritten, never confirmed); a record is never created unhomed (422), because nobody could read it and its key would block every re-sync. Filing, re-syncing and deleting are editor (`content.write`).

## Walkthroughs (`apps/walkthroughs`)
Router `apps/walkthroughs/api.py`; byte streaming `streaming.py`.
- **Token links.** `get_walkthrough` is `auth=None`: a `link` walkthrough is readable with a matching `?t=<share_token>`; a missing or wrong token 404s exactly like private. PATCH to `link` mints a token if none, to `private` keeps it (re-publishing revives the same link); `rotate-token` kills shared links.
- **Write gate** (`_may_write`): the uploader while still an editor of the workspace, or a workspace owner. Not a member is 404, a member who may only read is 403.
- **Stream** `/w/<workspace>/walkthrough/<id>/content` (`streaming.walkthrough_content`) is a bare view, Range-aware: session member OR (`link` AND correct `?t=`); another workspace's walkthrough 404s; the `<str:wid>` converter makes a malformed id 404 rather than reach the SPA. Every `content_url`/`video_url` the API returns is this path. There are no flat artifact addresses: [pages.md § Rules for every page](pages.md#rules-for-every-page); `tests/test_api_urls_are_workspace_scoped.py` fails on any artifact URL not under `/w/<workspace>/`.
- **Upload refusals** (`upload_walkthrough`): over `WALKTHROUGH_MAX_UPLOAD_BYTES` is 413; `cut_id` needs `kind=video` and a `narrative_review_id`, and `cut_scene_ids` needs `cut_id` (422); no Drive service account is 503 `drive-not-configured`. `WALKTHROUGHS_ENABLED` off makes the API and stream 404. A `style: recorded` narrative holds one video per cut, latest upload per cut wins; hero selection is `walkthroughs/pinned.py`.

## Reviews (`apps/reviews`) — the DDD gate
Router `apps/reviews/api.py`. A client polls a `ReviewRequest` until it resolves and reads `response_json`; do not change that contract.
- **Read** (`get_review`, `auth=None`): a member of the review's workspace, or anyone for a `link` review (tokenless); otherwise 404. A review in another workspace than the page's `ws` is 404. A null-workspace review is reachable by no member.
- **Decide** (`submit_review`): editor (`content.write`) in the review's workspace plus CSRF (re-run by hand because `auth=None`); an anonymous reader of a public review gets 403; an already-resolved review is 403. It mirrors into the storyboard's gate rows.
- **Suggest** (`suggest_review`, `auth=None`): never resolves the gate. Callers: an external reviewer with the review's `?t=` (no CSRF, the token is never ambient), or a member saving edits without deciding (CSRF-checked). Neither is 403; a resolved review closes suggestions. A malformed suggester email is dropped, never refused.
- **A narrative review's gate is also a decision row on its storyboard** (`storyboards/review_gate.py`): ruling it, or a round closing with it ruled, resolves the review server-side with the same `response_json` shape `submit` writes. `get_review_destination` returns the board address (the board token only for a caller holding the review's own valid `?t=`; may create the board), `null` for a findings review, which keeps its own page (`reviews/views.py::review_page`).
- **Run-child gates belong to no narrative.** `RUN_CHILD_GATES` (`apps/runs/ddd.py`; `product_findings`) hang off the run: `create_review` stores `narrative_slug=None`, `version=0`. `apps/runs/aggregate.py::_NON_NARRATIVE_GATES` is a superset: `external_release` is not a version but may create its narrative.

## DDD runs (`apps/runs`, mounted at `/api/ddd`)
Router `apps/runs/api.py`; aggregation `aggregate.py`.
- A narrative is identified by `narrative_slug`, inferred from the `ReviewRequest` and `Walkthrough` rows sharing it, independent of `run_id`; the server rejects narrative-less package artifacts.
- `get_run_release` is `auth=None`: workspace member OR `?t=<share_token>` on the primary artifact, checked in `aggregate.build_release`; a run in another workspace than `ws` is 404.
- **Writes are editor-tier** (`content.write`): visibility (cascades to every walkthrough and review under the slug), cascade deletes (a viewer who can see the target gets 403, anyone else 404), and `move_narrative`, which needs editor on the destination AND every source workspace, names only workspaces the caller is in, and is a dry run by default (the plan is the undo record). Same service: `manage.py move_narrative_workspace`.
- **Iteration sources** (`runs/sources.py`; roles are `NarrativeSource.ROLES`): nothing needed to keep iterating a narrative may live only on one machine. Editor of the pinned version's workspace writes, members read; identical bytes on a version and role are reused, changed bytes replace; version and narrative deletes drop them and a move carries them. Over `NARRATIVE_SOURCE_MAX_UPLOAD_BYTES` is 413; Drive missing 503. `tests/test_narrative_sources.py`.

## Shareouts (`apps/shareouts`)
`apps/shareouts/api.py`: posting is idempotent per `period`+`source` and replaces only the caller's own rows. `clear` removes the shareouts the caller posted where they are an editor, and every shareout in a workspace they own, never a teammate's otherwise and never another tenant's; an empty body clears all of those.

## Storyboards (`apps/storyboards`) — the shareable arc
Product tier. `Storyboard → Act → Entry`; an entry names a narrative by slug and resolves to its current release at read time. Router `apps/storyboards/api.py`; rounds `rounds.py`; decisions `decisions.py`.
- **Read** (`get_storyboard`, `get_board_narrative`, `auth=None`): a member of the board's workspace, or a matching `?t=`. A wrong token is 404, never 403 (`_readable_or_404`). `ws` 404s a board elsewhere and picks between two workspaces' same-slug boards. The narrative read 404s for a narrative not on the board, so a link to one arc is no read handle for the workspace.
- **Write** is editor (`_editable_or_404`: 404 to a non-member first, then 403 for a viewer). Minting or re-minting the link (`rotate-token` kills every link sent) is the same tier.
- **Feedback** (`leave_feedback`): a share-token holder is held to the board's single grant `read < comment < suggest` (403 when insufficient); any member bypasses the grant. `channel` and `target_kind` are server-set; a narrative not on the board is 404; an empty note is 422. It lives here, not in `apps/feedback`, because this app owns the token; it calls the request-free `feedback.services.ingest`.
- **Notes** (`list_notes`) are members only and 404 for a token holder: seeing other reviewers' notes would bias the independent read.
- **Feedback rounds** (`rounds.py`): open (editor) pins every narrative's current version and adopts the notes since the last round, 422 unless the board is linked to a project in its own workspace; close applies staged edits and creates and approves exactly one task on the board's project (a second close, or an unpicked disagreement, is 409); consume (the agent's PAT) refuses while any note is unanswered; deleting a note works only in the open round (409 otherwise); reading a round is members only.
- **Decision edits** (`edit_storyboard_decision`, `auth=None`, self-enforcing): inside an open round every edit is staged (a link holder needs `suggest`, else 403); outside one only a member may (409 for a link holder), and a review-gate row needs editor (403), and an undo of a resolved review is 409.
- Act identity is `Act.key`, never the row id, because both write paths recreate acts; the one derivation is `act_keys.py`. Authoring: `manage.py import_storyboard` (idempotent per `(workspace, slug)`, preserves the share token).

## Dynamic views (`apps/dynamic_views`, mounted at `/api/dynamic-views`) — generated screens in a sandbox
Product tier. Router `apps/dynamic_views/api.py`; safety model [dynamic-views.md](dynamic-views.md). Read `GET /guide/` (render contract and data catalog) before generating a view.
- Create/patch/delete/rollback need `agent.work` in the workspace OR edit rights on the named project (`_require_edit`); a view in a project is readable only by those who may read the project (`_readable_or_404`). Create validates the code defines `View`, every source against the catalog, every declared agent task (the agent must be in the view's workspace and one the author may give tasks to) and every declared connection call (422 names the fault).
- The frame (`GET /dynamic-views/frame/`) is not an API route: `DynamicViewFrameMiddleware` answers before sessions (it never sets a cookie), with a sandbox CSP and `connect-src 'none'`; the view reaches data only by asking the canopy page, which answers from the catalog as the viewer (`dynamic_views/frame.py` docstring).
