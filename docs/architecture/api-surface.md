# API surface

The rules a schema cannot express (gates, refusals, invariants), by route area. Routes, params and fields are in the routers (`apps/*/api*.py`, `schemas.py`) and `/api/openapi.json`; each area doc points to its router.
The machine-readable schema is `/api/openapi.json` (Scalar at `/api/docs/`, Redoc at `/api/redoc/`); frontend types are generated from it into `frontend/src/api/generated.ts`.
All routes are Django Ninja (Pydantic v2) under `/api/` unless marked as a bare view; errors are RFC 7807 `application/problem+json`.
The canonical tenant URL is `/api/w/{ws}/…`: `apps/api/tenancy.py::WorkspaceResolveMiddleware` 404s a non-member, pins `request.workspace_slug`, strips the prefix and reroutes to the flat mount, so the schema stays single. Handlers read `getattr(request, "workspace_slug", None)` (truthy = pinned, `None` = unpinned). What an unpinned list or create covers: [roles.md § A read that names no workspace stays inside one organisation](roles.md#a-read-that-names-no-workspace-stays-inside-one-organisation).

## Errors
Every error is RFC 7807 `application/problem+json`: `{type, title, status, detail?, instance?, extras?}` plus any extension members at the top level.
- `title` is stable per `type`; the per-occurrence message is always `detail`, so a client shows `detail` and falls back to `title` (`frontend/src/api/problem.ts::problemMessage`).
- A bare `HttpError(status, msg)` in a route becomes `type: about:blank`, `title` = the status's reason phrase (`"Not Found"`, `"Forbidden"`…), `detail` = `msg` (`apps/api/api.py::_on_http_error`).
- `ProblemError(status, title, type_=TYPE_…, detail=, members=, headers=)` (`apps/api/errors.py`) sets a typed problem; `members` are top-level keys a client branches on (`error: "step_up_required"`, `error: "device_proof_required"`), `headers` adds response headers (`WWW-Authenticate`).
- Outside a Ninja route (middleware, bare views) build the body with `apps.api.errors.problem_response(status, *, type, title, detail, **members)` — never by hand: it JSON-escapes text taken from the request (the tenancy 404 names the URL's slug) and defaults `title` the same way.
- **The schema says what a well-formed request is.** A rule JSON Schema can state goes in the schema: a length, a range, a `Literal`, a `pattern`. One it cannot — across fields, or against stored state — is declared on the route with `response={201: X, **refusals(422)}` (`apps/api/errors.py::refusals`) and said in its docstring; a declared refusal is documented as `application/problem+json`. The nightly contract fuzz (`tests/contract/`) accepts exactly the declared statuses as refusals of a schema-valid request.
- `apps/api/openapi_doc.py` corrects Ninja's document in one pass: every free-text request string gets a `pattern` excluding NUL (PostgreSQL refuses it in text and jsonb; the 400 "Value cannot be stored" handler answers it), and declared refusals are problem+json. Free-form JSON (`dict`, `Any`) cannot say that in JSON Schema, so `apps/api/nul_guard.py` (middleware) refuses a NUL anywhere in a JSON body under `/api/` — value or key, any depth — with that same 400, before any view runs; multipart and other bodies are not read. A `StrictModel` string with a minimum length is documented as already trimmed (`apps/common/schemas.py::strip_means_non_blank`), since it is stripped before it is measured.

## Auth + session (root) and the bare views
Routes in `apps/api/api.py` (`/api/me/…`, health, csrf) and the views outside Ninja; `config/urls.py` lists the bare mounts. Read the code for shapes; the rules:
- `GET /api/me/`: `passkeys_here: false` on a session minted from a token (the Canopy Runner app's); every step-up and approval is refused on it, and the SPA hands each passkey moment to the browser (`frontend/src/auth/passkeyHere.ts`). `/api/health/` and `/health/` are public; `/health/` adds `runner_code_sha`, which a developer-install updater reads when canopy refuses its token.
- The personal settings under `/api/me/` (presence preference, runner-app page, canopy-projects opt-in, session workspace) are the caller's own and audited: `ProjectOptIn` (unset = none: a repo outside it gets no repo turn routed and no session, transcript or usage mirrored → [runners.md § Opted-in projects](runners.md)). The session-workspace choice must be a workspace the caller is editor+ in; it files NEW emdash sessions only, existing ones stay put.
- `/auth/cli/authorize/` (`apps/tokens/cli_authorize_views.py`): a signed-in browser mints a `PersonalToken` and 302s it only to a safe loopback callback (`_validate_callback`); a non-loopback target is refused so the token cannot leak.
- `/download/runner/<platform>` (`apps/harness/views.py::download_runner`): signed-in only; unknown platform or nothing built is an HTML 404.
- `/auth/github/*` (`apps/github_connect/github_app.py`): signed-in only; the callback path is registered on the GitHub App, so do not move it.
- `/auth/connections/{provider}/{workspace}/start|callback/` (`apps/connections/views.py`): the module docstring is the contract (reasons, `return_to`, `temporary`, the agent flow). Rules to keep: an agent's start is a CSRF-checked POST only (GET is 405) and is an admin-of-that-workspace act checked again at the callback; a person's flow finishes only for the user who began it; the token is sealed to the owner's vault key at the callback and nothing readable is kept → [vault-connections.md § OAuth connections are sealed to their owner](vault-connections.md).
- `POST /api/auth/contact-token` (`apps/contacts/contact_api.py`, `assertions.py`; `auth=None`): the credential is a host site's signed assertion about its visitor. `contacts.services.resolve_arrival` returns a delegated USER token (`assurance = host_signed`) only for a linked contact, or a verified email held by exactly one active canopy user who is a member of the site's workspace; otherwise a contact token. It never creates an account; membership is the whole gate. A signed `canopy_agent` claim must equal `agent_slug` (400 `agent_mismatch`) and be on the site's allow-list (403); the token then serves that one agent only → [embedding-advanced.md § 5c](embedding-advanced.md).
  - Host grant at arrival (contract: `sdk/python/README.md`): an optional `id_jag` is verified and redeemed by `apps/host_grants`; a refusal never fails the arrival (an `Event` in `tokens.host_grants` says why). A contact never gets a usable grant (no passkey to confirm it). Every outbound fetch is https-only, refuses private addresses and follows no redirects (`apps/host_grants/outbound.py`).
- MCP client sign-in (`apps/oauth_server/mcp_oauth.py`): public PKCE (S256) clients only; `/oauth/authorize` needs a signed-in person and refuses a token-minted session; an unknown client or unregistered redirect is shown, never redirected to. The access token is a `PersonalToken` tied to an `OAuthGrant`; lifetimes, rotation and reuse revocation → [mcp-surface.md § Auth model](mcp-surface.md#auth-model).
- canopy as an OAuth client and as host of its own MCP (`apps/host_grants/client_identity.py`, `self_host.py`): `/oauth/client.json` and `/oauth/jwks.json` publish canopy's CLIENT identity (the DPoP key is never published; neither key can assert a user; 503 without the key settings). The host half is off until `CANOPY_HOST_SIGNING_KEY` and the client keys are set; `/oauth/host/jwks.json` is the HOST key, distinct from `/oauth/jwks.json`; `/oauth/probe` answers only for the dedicated probe user and canopy's own client (404 without one). canopy's own redemption reaches these in-process (`self_host.loopback_*`); the gateway's MCP call is real HTTP.
