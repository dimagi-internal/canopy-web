# Pages: workspace agents

The tenant-scoped pages for agents: the agents table, creating an agent and the agent workspace with its sub-routes. Part of the [pages](pages.md) topic; the index there lists every part. The agent workspace is `pages/AgentWorkspacePage.tsx` with its rail sections as the `agents/:slug` children in `frontend/src/router.tsx`; each section is a component in `frontend/src/pages/agents/`. The agents table reads `GET /api/agent-roster/`.

## Cross-cutting rules

- **Open alerts about the agent show above every rail section** (`AlertList scope="agent:<slug>"` in `AgentWorkspacePage.tsx`, nothing when there are none; [`alerts.md`](alerts.md)).
- **Create (`/agents/new`, `NewAgentPage`)** drives `POST /api/agents/scaffold` then the ordinary upsert, then saves the same token as the agent's GitHub identity (`apps/agents/api.py::scaffold_agent`, which states what it adds and that it overwrites nothing). Delete (`DELETE /api/agents/{slug}/`) is the agent's owner or a workspace owner and closes its open sessions; its projects and tasks stay, led by nobody (`apps/agents/api.py::delete_agent`).
- **The agent's Mail section and a person's own Mail (`/w/:ws/mail`) are one client** (`components/mail/MailClient`); they differ in source (`agent` vs `forwarded`) and in who the server lets send: an agent's mail needs FULL on that agent (`apps/mail/api.py`), a person's own forwarded mail needs no agent right. Message HTML renders only in the sandbox of `components/mail/MessageView` ([`mail.md`](mail.md) § Safety invariants).
- **Triggers fire with their creator's authority**, and stop (with the reason shown) when that person loses the right ([`access.md`](access.md) § Triggers; `apps/harness/triggers.py`).
- **Skill history is read from the agent repo's git history** with the owner's GitHub grant (`apps/agents/api_skills.py::get_skill_history`; `AgentHistorySection.tsx`).
- **Capabilities:** a grant may only lower the manifest's limits, and the server's refusal is shown verbatim (`apps/capabilities/services.py`, `apps/capabilities/api.py`). Granting is for workspace admins (`integrations`).
- **Settings has one tab per question** (`pages/agents/settingsTabs.ts`: `SETTINGS_TABS`, `ANCHORS`). Every old `settings#<anchor>` link forwards to the tab holding the anchor, and a tab with an open setup step carries a dot. The setup checklist is `apps/agents/setup.py` (`GET …/setup`); a zero-knowledge agent's vault step comes before its mailbox.
- **The agent's vault is the shared `VaultView`** (`components/vault/`, adapter `pages/agents/AgentSecretsPanel.tsx`; editor `components/vault/VaultEditor.tsx`, owner-agnostic so other vault pages reuse it). Values are encrypted and revealed in the browser; the trust model is [`vault.md`](vault.md). The agent's canopy login lives apart from the vault (`AgentCanopyLogin.tsx`, `AgentSecurityPanel.tsx`).
- **Google mint:** the consent must come from the account the server expects (`apps/agents/credentials/google_oauth.py::expected_account`); anything else returns `?google=wrong-account&account=<x>&expected=<y>` and stores nothing (`apps/agents/credentials/google_mint.py`). A `zk-no-recipients` result links to `/settings#vault-key`.
- **Connect your Google account (`connect/google`, `ConnectGooglePage.tsx`)** is for an agent's admins only: a non-admin is refused 403 `not_an_admin` (`google_mint.py::start_delegated`). The credential is withdrawn at `/settings/agents` → Your credentials delegated to agents ([`vault.md`](vault.md) § Connect your own Google account).
- **Retired rail addresses redirect, keeping the query** (`KeepQueryRedirect` entries in `router.tsx`).
