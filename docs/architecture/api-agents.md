# API: agents

Rules the schema cannot express for an agent as an instance row: who may change what, the refusals, and the invariants. Part of the [api surface](api-surface.md) topic. Routes, bodies and status codes are in the routers named below and in the OpenAPI schema; this page does not repeat them.

An `Agent` is an instance row (its definition is the repo). Tasks and projects are the workspace's ([work.md](work.md)); `/api/agents/{slug}/…` is that agent's view of them. Roles and access: [access.md](access.md).

## Agents (`apps/agents/api.py`, `apps/agents/views.py`)
- **Read vs write gates.** Every route resolves the agent through `gates.py` (`agent_for_read` first, so a non-member always gets 404, never 403): `agent_for_work` = `agent.work` (editor), `agent_for_edit` = `agent_edit` on the agent (`access.may_edit_agent`; the 403 names who can give the role), `agent_for_admin` = owner, admins, workspace owners (`Agent.is_admin`).
- **Upsert** (`api.py::upsert_agent`). Creating needs an editor of the target workspace and makes the caller the owner (`_creating_owner`: from inside an agent's live turn, the person who asked for it); an update never changes the owner. A non-member of an existing agent's workspace gets 404 (the slug namespace is global, so 403 would be an existence oracle). Changing `SELF_FIELDS` needs `agent_edit`; changing `services.DEFINITION_FIELDS` (repo, engine, secrets, sources) needs an agent admin, because whoever names the repo writes code that runs with the agent's credentials. A field sent with the stored value is not a change. A `workspace` other than the current one is the full move below.
- **Move** (`api.py::move_agent`, rules in `move.py`'s docstring). One transaction or nothing; the dry run and the move share one code path. Needs an agent admin where it is and editor in the destination; a missing destination and one the caller is not in are the same 404. A project of another workspace the agent leads refuses the move (409) until handed on.
- **Delete** (`api.py::delete_agent`): the agent's owner or a workspace owner only. Open chat sessions are closed first; tasks and projects stay, led by nobody.
- **Scaffold** (`creation.py`, `api.py::check_scaffold_repo` / `scaffold_agent`). Uses the caller's own fine-grained GitHub token, used once, never stored. `check` is a POST only to keep the token out of the URL. Nothing already in the repo is overwritten; another agent's repo is refused. Registering is the ordinary upsert; the slugs `new` and `scaffold` are reserved (`_RESERVED_SLUGS`).
- **Canopy login** (`api.py::link_canopy_user`, `mint_agent_canopy_token`, `give_agent_canopy_login`; `services/agents.py::mint_agent_canopy_token`). An agent's login is always the account at its own `Agent.email`, never any other. Linking someone else's signed-in account is not done: an `AgentLoginRequest` goes to that person, who accepts in their own browser behind a passkey (`api_login_requests.py`). Minting a token for a login that has ever signed in interactively needs a workspace owner (it may be a person's). `canopy-token` returns the secret once, so a token-minted caller is refused (`minting_refusal`); `canopy-login` stores it sealed and never returns it.
- **Owner and admins** (`api.py::transfer_owner`, `grant_admin`, `revoke_admin`). Transferring, clearing (workspace owners only) and granting or revoking admin are the agent's owner or a workspace owner, because admin hands over the agent's credentials. The new owner or admin must be a workspace member (422); the owner cannot be revoked (422). An admin grant is inert if the holder left the workspace.
- **Turn mode** (`api.py::set_turn_mode`): `manual` from any editor, `auto` only from the owner or an admin (`refuse_auto_unless_admin`). The upsert cannot touch it.
- **Repository, CLIs, Slack** (`api.py::set_repository`, `set_agent_clis`, `set_slack_enabled`): agent admin; a repo or CLI change is a `DEFINITION_FIELDS` change, audited. A changed repo asks cloud boxes to re-bootstrap (`setup.py::request_setup`). CLI list refusals: `clis.list_refusal` ([runner-routing.md](runner-routing.md#which-cli-runs-a-turn-appsharnessclispy)).
- **Setup checklist** (`api_readiness.py`, `setup.py`): each step reads the predicate the system itself uses; none is a second opinion.
- **Roster** (`api.py::agent_access`, `access.py::roster`): computed with the predicates a turn uses, pinned by `tests/test_agent_access_roster.py`.

## Access list, roles, defaults, read mode and host sites
- **Access list** (`api_access_list.py`; [access-agent-roles-and-access-list.md](access-agent-roles-and-access-list.md#the-access-list)). Any member reads; an agent admin writes, and only the agent's own lines (an inherited line is changed on the workspace, 404 here). A line names people only by address (domain, contact) may give only a role that reads or opens host sites (`grants.py::LineError`). A line gives a role or one host site, never both. Every write is a settings change `access-list:<slug>`.
- **Workspace default lines** (`api_access_list.py::_require_default_rights`): a workspace admin (`members.manage`); a default that lets people drive or change every agent is the workspace owner's.
- **Roles** (`api_roles.py`; [§ Configurable roles](access-agent-roles-and-access-list.md#configurable-roles)). A workspace admin defines roles; one that drives or changes the agent (`roles.drives`) is the workspace owner's, before or after the edit. Every write takes a passkey step-up from a browser; a token may write only a role that does not drive (`_machine_may_not`). Taken or clashing key, built-in delete, role still in use: 409 (`roleadmin.py`).
- **Read mode and host sites** (`api_answering.py`, `profile_settings.py`, both stored in `Agent.interface`). Any member reads; the owner or an admin writes; `dry_run: true` validates without saving or auditing. A document the plain settings cannot hold (`profile_settings.document_problems`) is refused and left as is. `published_profiles.py::parse` is strict: unknown keys, the keys `full`, `editors`, `callers`, `role`, `pages`, and a `callers_default` other than `none` are 422; a row that could leak sensitive data is refused (`sensitive_data.structural_refusals`). Neither has a `role`: who may use them is the access list. `/api/agents/{slug}/interface*` answers 410 to everyone (`views.py::retired_interface_route`, a bare view in `config/urls.py`, so in neither OpenAPI nor the MCP tools).
- **How a turn gets its access**: `turn_context.resolve_turn_context` at enqueue and again at claim ([access-turn-context.md § Two moments](access-turn-context.md#two-moments-enqueue-and-claim)); a refusal is one `refusals.Code`.

## Skills (`apps/agents/api_skills.py`, `skill_catalog.py`, `skill_history.py`)
- `PUT …/skills/` needs `agent_edit` (`@gate("agent-edit")`). The merge of runner reports into the catalog, and what a report is not trusted to do, are in `skill_catalog.py`'s module docstring.
- Skill history reads the repo with the **owner's** GitHub grant, never the viewer's or a runner's, so `repo_url` is validated to a bare `https://github.com/<owner>/<repo>` before anything touches git or the token (`skill_history.py` module docstring). A read serves stored history if the refresh fails; `POST …/skill-history/sync` needs `agent_edit`.

## Syncs, turns, runtime
`api.py::create_sync`, `create_turn`, `get_agent_runtime`. Writes are `agent.work`. `create_turn` is idempotent per `(agent, cli_session_id)` and attaches to the dispatched `harness.Turn` by `session_key`; a turn list redacts content per `turn_access`.

## A2A Agent Cards (`apps/agents/api_a2a.py`, `agent_card.py`)
A card grants nothing; every turn is authorized at enqueue by `turn_context.resolve_turn_context`. The public card exists only when an address-only access-list line reaches read mode or a host site; every other case (no such agent, member-only, outsiders only via an editor line) is the same 404, so a private agent's existence does not leak. The extended card needs a session or PAT (a contact token leaves the request anonymous, so it is refused). `/api/a2a/` is public in the login middleware (`PUBLIC_PATH_PREFIXES`) and each route self-enforces. Never emitted: `tools`, `bash`, `read_paths`, `entry`, `input`, the access list, the workspace. Mapping, caching and the unsigned-card note: `agent_card.py`'s module docstring.

## Agent runs (`apps/agent_runs/api.py`, `documents.py`)
Reads are members; creating a run, gate, verdict, fork, and run-document writes are `agent.work` or the agent's own login (`_store_for(write=True)`). Every handler goes through the `RunStore` Protocol (`resolver.get_run_store`), never a store directly.

## An agent's state document (`apps/harness/api_agent_state.py`, `agent_state.py`) and coaching facts (`apps/canopy_sessions/api_coaching.py`)
Write: the agent's own login inside a running, unconfined turn of it. Read: the owner and admins, or that same turn only when it answers to nobody or to one of them (a read returns everyone's records). Anyone else 404. 409 on a stale `expected_version`, 413 over 1 MiB. Rules: [runners.md § An agent's state document](runners.md#an-agents-state-document). Coaching facts: ids and closed words only, same login and turn, and a fact about a person needs that person's live review grant ([analytics.md](analytics.md)).

## Agent tasks (`apps/agent_tasks/api.py`) and threads (`apps/threads`)
Agent tasks: contract and completion rule in [agent-tasks.md](agent-tasks.md). Anyone not allowed gets 404, never 403; only the agent's own login submits a result, and that is the only way a task completes.

Threads: a message is a turn tagged `origin_ref = {kind: thread_message, …}`; the limits (closed or expired thread, non-participant, wrong speaker, out-of-order `n`, budget) are enforced where the turn is created (`threads/guard.py`), not by the moderator. A thread cannot be opened from inside a thread message. Opening and closing are `agent.work` (`threads/api.py`).
