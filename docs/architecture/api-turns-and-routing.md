# API: turns, triggers, schedules and routing

Rules for the routes that start and run turns. The routes, params and shapes are in the routers and `/api/openapi.json`; this page keeps what they do not say. Part of the [api surface](api-surface.md) topic.

Start reading at: `apps/harness/api_turns.py` (enqueue, read, start/finish/cancel/abort), `turn_gates.py` (the enqueue gates), `api_schedules.py` + `schedule_services.py` + `triggers.py` (triggers and schedules), `apps/agents/api_routing.py` (agent routing writes), `api_session_sync.py` (runner-reported sessions), `api_investigations.py` + `auto_debug.py`, `api_local_turns.py` + `local_turns.py`.

## Triggers and schedules
- **Who may write** (`triggers.may_set_up`, called by `schedule_services._check_may_set_up`): a cron trigger needs `agent.work`; an `inbound_mail` trigger, an `auto` one and any **job** need an agent admin (403; for a job the sentence is "Only an admin of {slug} can change a job."). `run-now` on a job asks the same. A trigger has no authority of its own: it fires as its creator, and one whose creator lost the right does not fire (`triggers.refusal`; `run-now` and `fire` answer 409 and consume the slot).
- **A plain job** (`schedule_services.validate_job`, `_apply_job`, `ScheduleIn.job`/`job_repo`): both or neither (422); only a cron trigger may have one; routing is forced `cloud_only` and grace is at least `JOB_MIN_GRACE_MINUTES`. The command is never in any payload: the box reads it from the repo's `.canopy/jobs.yaml`, so the name/repo shapes are the whole defence (no `/`, no `..`, no URL). Only a cloud box reporting `capabilities.jobs` claims one (`claim.claim_next_turn`, `routing_orders.job_refusal`), at most one at a time per `Runner.machine_id` (`routing_orders.holds_a_job`). A slot not taken within `schedule_turns.LATE_SLOT_WINDOW_MINUTES` is `MISSED` unless `always_run`; `run-now` on a job still running is 409 (`schedule_turns.JobStillRunning`).
- **A failed job's review task** (`AgentTask.job_schedule_id`) never starts a model turn: `approve` and `nudge` are refused 422 and a `reply` is recorded as a note, on every task route (`agents/services/task_actions.py`).
- **Occurrences**: the `Turn` is the occurrence (`idempotency_key = sched:<id>:<slot>`); a runner's fire of a slot the server clock (`schedule_clock.py`) already fired collapses onto that turn. Firing slot N+1 marks slot N's unfinished turn `MISSED`; `run-now` supersedes an open occurrence and never advances `last_slot`. Semantics: [runner-flags-and-schedules.md](runner-flags-and-schedules.md) → "Scheduled turns".
- **Route order**: `schedules/preview` must stay declared before `schedules/{schedule_id}` (comment above `preview_cron`).
- The server clock, `preview` and the runner all compute slots with `packages/canopy_cron` (`next_slots()` / `due_slot()`), which owns the `croniter` bound: do not change it casually, a major bump changes slot math.
- Runner-facing: `GET /api/harness/schedules/` is tenant-scoped from `runner.owner`, never `capabilities`; `fire` is 404 for a schedule this runner may not fire (`api.py` schedule routes).

> **Deleting a user strands their runners.** `Runner.owner` is `SET_NULL` and a NULL owner has no tenant (`runner_tenant_slugs` fails closed): every claim and schedule route returns nothing for that box, which can only be retired and re-paired. Deactivate a departing user (`is_active=False`) instead if their runners should keep working.

## Routing writes (`apps/agents/api_routing.py`; the order and claim: [runner-routing.md](runner-routing.md), [runners.md](runners.md))
- **Every write that points an agent at boxes** (default list, source rule, actor route) passes `_runners_for_routing`: a runner the write ADDS must live in the agent's workspace or above, be one the caller administers (403 naming it) and be holdable by the agent (`services.runner_may_hold_agent`, 403); a runner the write merely KEEPS is not re-checked, or nobody could save a shared rule. An invisible or unknown runner is 422 "unknown", never 403, so a guessed id learns nothing. A runner kept from the agent by what it serves is 422 (`routing.serves_refusal`).
- `PUT …/runners` takes exactly one of `runners` / `runner_ids` (422), replaces only the `source=""` rows, and an empty list makes the agent follow its workspace order (`routing.inherited_orders`). A disabled row keeps its rank, never routes, never blocks a lower rank and stays drillable.
- **`turn_mode=auto` on a rule or actor route** is set only by an agent admin; keeping an existing `auto` is free (`route_refusals.refuse_auto_unless_admin`, `api_routing._refuse_new_auto`). An `auto` naming a person applies only to a verified message (`turn_mode.resolve`).
- Actor routes: `strict=false` falls back to the agent's usual runners after a minute; actors are normalized to a bare lowercase address and an unparseable one is 422.
- Pinning a chat (`pinnable-runners`) and `route-preview` read the claim's own predicates (`canopy_sessions.placement`, `routing.labelled_assignment_rows`), so what they say is what the claim does.

## Enqueue, read and cancel turns (`api_turns.py`, `turn_gates.py`)
- **Idempotency** (`services._replay`, `IdempotencyConflict`): a key is unique per WORKSPACE (`Turn.idempotency_scope`) and replays only to the target it was made for (same agent, chat session or project); anything else is 409 saying nothing about the turn holding it. A replay is returned through the same content gate as a read.
- **Origin**: only `Turn.POSTABLE_ORIGINS` (`api`, `ace_web`, `email`, `slack`) may be posted; `canopy_web_chat` and `canopy_scheduler` come from in-repo producers. An `email` turn may be posted only by an agent admin (the runner that read the mailbox): it names its own asker and the DMARC verdict from `origin_ref`, so letting an editor post one would let them promote themselves (`check_email_poster`).
- **Pin** (`resolve_pin`): an unseen or retired runner is 422; 403 if the box cannot hold the agent, does not offer the project repo, or the caller may not pin (agent admins pin any holdable box, others only boxes they administer: `access.may_pin_runner`). A requested `turn_mode` is checked up front (`auto` for admins only); `cli` must be one the agent is set up for (`clis.refusal`).
- **`reads_for`** (`check_reads_for`): only an agent's own login, inside a turn nobody asked for, may scope a turn to one person, and only one with a live review grant (403/422). The scope passes on to whatever the turn starts.
- **Reads**: list and get are redacted per `turn_access`; events/transcript/messages/caller-context need the content-read gate (`turn_access.can_read_turn_content`); a sensitive turn's event ledger reads as a log (`can_read_turn_log`). Every turn read carries `canopy_session_id`/`canopy_session_url` (what `canopy-sessions/{id}/send` takes), not the runner's own `session_id`.
- **Reporting** (`start`, `finish`, `events` POST, `transcript` POST; `api.reporting_turn_or_404`): the owner of the box that claimed the turn; an unclaimed turn takes the cancel tier; a direct (`origin=local`) turn takes its initiator only, not even an editor. `start` is 409 unless claimed/running; `finish` is idempotent on a terminal turn; an unknown event kind is 422. Transcript appends are idempotent per `batch_id`, 422 over `TRANSCRIPT_APPEND_MAX_BYTES` per request, truncate with a marker (never a 4xx) past the per-turn ceiling in `ledger.append_transcript`, and are allowed after finish.
- **Cancel** (`_cancel_refusal`): queued only (409 once claimed), idempotent on a terminal turn; agent turn needs `agent.work`, a chat turn write access to the chat or your own send, a project turn its initiator or `agent.work`. **Abort** (`abort_turn`): its own agent's login, an editor, or the claiming box; ends a turn FAILED and raises it as a failure; 409 for a turn that ended another way.
- `GET /turns/unclaimable` is composed from the claim's own predicates (`claim_reach.unclaimable_queued_turns`); a caller in two tenant trees must pin one (422). A turn with a stored `capability` goes only to a runner reporting `PROFILES_VERSION`/`ENVELOPE_VERSION` (`routing_orders.profile_q`), not bypassable by a pin.

## Claim (`api_runners_protocol.py::claim_turn`)
Returns `ClaimedTurnOut`: the turn, its credentials (`claim_payload.issue_credentials`, shared with the WebSocket claim) and the caller envelope (`caller_context`), which only the claim carries; `GET …/caller-context` returns the same document under the content gate. The runner writes the envelope to `~/.canopy/caller/<turn_id>.json`. `X-Canopy-Acts-As` claims in a lower role. Order: [runner-routing.md](runner-routing.md) → "The claim".

## Sessions a runner reports (`api_session_sync.py`; chat semantics [chat-sessions.md](chat-sessions.md), menus [blocked-agent-menus.md](blocked-agent-menus.md))
All gated `runner` (the box's owner; anyone else 404). Rules the routes do not make obvious:
- `sessions` is a wholesale report: absence from a `complete` report retires a session; a report never clears `RunnerBinding.runner` (durable identity, not liveness). A NEW session is filed under its project's agent (in the runner's tenant), else the owner's default session workspace, else the runner's workspace; existing sessions are never re-filed (`session_sync.replace_reported_sessions`).
- `record-session` is 404 for a session that is not this agent's or not in the owner's tenant; with `turn_id` the server names the session from the turn.
- A **sensitive-data box** keeps its transcripts to itself: `streams` and `backfills` answer empty for it (`is_sensitive_data_box`); a confined conversation has no binding, so `closes` never names it and the box asks `kept-conversations` instead. Transcript rows are persisted whether or not anyone watches; `live` only controls fan-out.
- **Handoffs** (`_handoff_for`): `capture`/`archive`/`captured`/`close-result` are the SOURCE runner's, `archive` GET/`restored` the target's (or the box the session is on now); any other runner, or a session whose words were deleted, gets 404. Only a verified restore lets the source close its task.
- Menus, interrupts, close results and subagents are matched by id (`answer_id`, `interrupt_id`, `(runner, project, task name)`); a result for a superseded one answers `{ok: false}` and clears nothing. Interrupts are offered for `control.INTERRUPT_TTL`.
- Admission notices: `apps/admission/runner_notices.py`, [access-direct-use-and-admission.md](access-direct-use-and-admission.md) → "Admission rules".
- Runner software versions and what the cloud runner does each tick: [runner-credentials.md](runner-credentials.md) → "The runner software".

## Readiness drills (`apps/harness/api.py::start_runner_drill`, `drills.py`)
Starting is the runner-admin tier plus agent admin of each drilled agent unless the caller owns the runner (default fan-out narrows to those, 422 if none; naming another is 403). Disabled assignment rows are drilled on purpose (drill before enabling). Results: runner administrators or a `logs.read` holder in the runner's tenant, else 404. The `report` callback takes the signed `?t=` link, the drilled agent's own login or the runner's owner; a drill turn that ends with no report is marked `fail` even if the turn was `DONE` (`services.py::finish_turn` → `turn_close.close_turn`).

## Auto-debug (`auto_debug.py`; routes `api_investigations.py`)
The module docstring holds the lifecycle, dedupe and rate-limit rules. Invariants to keep: a failed debug turn never spawns another; a fix that did not hold goes to a person, not a new debug turn; the hook never fails the finish that called it. Access (`auto_debug.can_handle`): the workspace's `logs.read` holders, the debugger agent's admins and its own login; anyone else gets 404; a list needs one tenant tree. After `hand-off` the debugger's own `resolve` is 409. [alerts.md](alerts.md) covers the alert side.

## Direct use (`api_local_turns.py`, `local_turns.py`; why: [access-direct-use-and-admission.md](access-direct-use-and-admission.md) → "Direct use of an agent")
- Private runners and `…/local-turns` are the caller's own rows only; a non-member or someone else's private runner is 404, a runner token signs in only its own private runner (403).
- Opening a direct turn needs `turn_context.resolve_turn_context` to give the WHOLE agent (403 otherwise); `turn_mode: auto` is honoured only for an agent admin. The turn is RUNNING from the start, never claimed or routed, with an `LOCAL_LEASE` lease the prompt hook renews (initiator only). Finishing and transcript use the ordinary turn routes (see Reporting above).
- Licenses (`apps/agents/api.py::approve_agent_license` / `revoke_agent_license`): agent admins only; approve is 409 unless the access list gives the person the whole agent; a revoked license is never re-issued automatically. `/credentials/resolve` and `/credentials/access` take `via: "license"`: an active license plus the caller's own running direct turn named in `X-Canopy-Turn-Id`.
