# API: Slack, mail, inbound push and the embedded widget

The rules for the channels people reach agents on: Slack, workspace mail, inbound push, Web Push and the embedded widget. Part of the [api surface](api-surface.md) topic. Routes, fields and gates are in each router file and the OpenAPI schema; this page holds what they do not say.

## Inbound push (`apps/inbound`) — the doorbell
Framework tier. Gmail push turns new mail into a turn in seconds instead of on the runner's 300 s poll. Router: `apps/inbound/api.py` (module docstring states the two response rules).
- **Verification.** `gmail_push` is `auth=None`, allowlisted in `apps/common/middleware.py`, and checks a Google-signed OIDC JWT against **that workspace's** `InboundPushConfig` (the tenant is in the path, so no payload byte chooses the credential and one tenant's signer never satisfies another's). Unverified is **404** (no enumeration); verified but not actionable is **200** (a 4xx makes Pub/Sub redeliver forever).
- **A doorbell, not a reader.** A push carries `{emailAddress, historyId}` and no content. `inbound/services.py::handle_push` resolves mailbox, agent and runners through `routing.assignment_rows_for(..., ORIGIN_EMAIL, ...)` (the rows the claim uses, so a strict `email` rule holds) and sends `runner.check_inbox` to each online assigned runner. No mail credential lives in the web app; a forged doorbell causes at most an empty read. Enqueue is idempotent per `(thread, messageCount)`.
- **The poll audits push.** `inbound/signals.py` writes `gmail.push.missed` at `error` when an email turn with `origin_ref.discovered_by == "poll"` appears on a mailbox with a live watch. Stamps are per mailbox.
- An address is globally unique across workspaces (a push carries nothing else to disambiguate on); `create_mailbox` answers 409 without naming the holder. `report_watch` is editor+ (`events.write`) because a watch expiry decides whether its alarms fire; a non-member gets 404.
- Watch arming and the GCP constraints: [gmail-push-provisioning.md](../runbooks/gmail-push-provisioning.md). Configured only at `/w/:workspace/settings/inbound`; there are no deployment-global inbound settings.

## Slack (`apps/slack`) — the Slack channel
Framework tier. A Slack thread becomes a `canopy_sessions.Session` and each message a `send_message(origin="slack", …)`. Routers: `apps/slack/api.py` (`/api/slack-config`), `ingest_api.py` (`/api/slack-ingests`), `session_api.py` (mounted at the session paths), webhooks in `views.py`, OAuth in `views_auth.py`. The route docstrings state each call's contract.
- **Webhooks** (`/api/slack/events|commands|interactions`) are bare views, allowlisted and self-enforcing on the Slack signing secret. A verified request always gets **200** (non-2xx makes Slack redeliver); refusals go back as ephemeral messages. Unconfigured is **503**.
- **`/api/slack-config/` is deliberately not under `/api/slack/`**, which is allowlisted for Slack's anonymous webhooks.
- **Install and tenants.** `views_auth.install` is owner-only; one Slack can serve several canopy workspaces (`SlackWorkspaceLink`), connecting adds a link and refreshes the shared bot token. A message's tenant is what it is ABOUT (its thread's session, else the agent it names), never the Slack it arrived through (`services.resolve_principal`). `views_auth.link` joins a Slack user to the signed-in canopy user only when the Slack profile email equals the canopy email.
- **Config gates.** App configuration token, `declare-agent` and the workspace-wide channel-ingest switch are owner (the switch off also stops live reads); the history policy, sync and channel allow-list are `integrations`. Giving the configuration token from a browser needs a passkey step-up (a token does not). Declaring the app an agent is one-way (Slack cannot undo it). `PATCH /api/agents/{slug}/slack` is `agents/api.py::set_slack_enabled`.
- **Whole-channel reads** (`apps/slack/ingest.py`; the module docstring lists the guarantees). The permission is given in Slack, never through this API: `POST /api/slack-ingests/` only creates a `pending` ingest and posts one Approve/Decline message. Approve needs a person who is in the channel now AND holds `integrations` in the agent's workspace or created the channel; the agent's own login can never approve or decline. An allow-listed channel is refused (409) on this route: it is read only when a person types `/<agent> read-channel <ask>`. The transcript and read-mark routes are the agent's own login ONLY (not its owner); revoke also takes the approver (`ingest.may_revoke`) and deletes the transcript. The read mark is a stored-row id, not a Slack ts, so a follow pass that stores an old thread's reply late is never skipped. The read runs off-request (`ingest_scheduler.py`, `SLACK_INGEST_TICK_S`); every step is a `slack.ingest_*` event.

**Who is asking** (`services.resolve_principal`, `slack_user`). A Slack user resolves to a member by an existing link, else by profile email (`auto_link`); anyone else is a `Contact` (`source="slack"`) answered as one, and their session has no `created_by`, so no member opens it. Only a blocked contact is refused. A member's session is private to the thread's starter. A confined reply in someone else's thread forks to a thread of its own (`services._fork_confined`, one per thread and person). `@canopy branch <ask>` splits a conversation (`branch.py`; starter or agent admin only). A reply into a thread a repo session was shared into is members-only (`services._continue_shared`): that session is somebody's own Claude Code session.

**Replies and status** (`relay.py`, `status.py`). Exactly-once relay via `SlackRelayPost` (unique `turn, seq`); a failed post writes `slack.relay_failed` and is not retried. A reply in a thread whose session was **closed** is never sent and never dropped silently: one public notice with a button that starts a new session seeded with the thread (`services.restart_from_click`, judged like a message from the clicker, so a confined clicker still forks). Turns before `slack_bound_at` are not relayed. Redelivery collapses via `client_id = slack:<channel>:<ts>`. Status rendering: `chat-sessions.md` § Turn status.

**Dialogs over Slack** (`menus.py`, `SlackMenuPost`). Thread replies are parsed strictly and go through the same `answer_menu` as the phone; anything else while a parsed dialog is up is not sent. Button values are re-checked against what is open now. An option-less Notification marker captures no replies.

**Sharing a session TO Slack** (`share.py`, `session_api.py`; MCP `share_session_to_slack`, `start_new_slack_thread`, `detach_session_from_slack`, `take_session_offline`).
- Reply buttons (`choices.py`, `SlackChoicePost`) send their `reply` through `services.deliver_choice`, after `services.choice_refusal`: a click from someone whose typed reply would not reach the session does nothing and leaves the button. The click is claimed under the post's row lock.
- A bound **repo session** accepts replies from workspace members only. A bound session that closes (archived, closed in canopy, or absent from two consecutive complete runner reports, `RunnerBinding.missed_reports`) gets its thread told once.
- Detach moves the `slack_*` keys to `metadata.slack_detached`, deletes nothing; re-attaching is a fresh bind. Session payloads carry `slack` from the reader Slack registers in `canopy_sessions/channel_bindings.py` (canopy_sessions imports no Slack).
- **Agents and their own conversation.** An agent's own login cannot read a Slack thread a person started, but `access.own_turn_session` lets it act on the ONE conversation of a turn it is running, named by `turn_id`, while that turn is claimed/running/needs_human: update its thread, detach it, re-bind only in that conversation's own channel, or move it to a new thread there (`start_new_slack_thread`). The caller envelope's `conversation.slack` comes from `location.py` (cached on the session, never fetched while building).

## Push (`apps/push`) — Web Push for `/supervisor`
Router `apps/push/api.py`; delivery `apps/push/services.py`.
- Push needs **both** `VAPID_PUBLIC_KEY` and `VAPID_PRIVATE_KEY`; either empty means the endpoints 503 and sends are skipped.
- A subscription endpoint is an outbound URL a signed-in person typed, so `_refuse_unsendable` rejects non-https, credentialed and private/internal hosts (422); it is deliberately not a host allowlist. The endpoint belongs to the browser, so a subscribe re-points it at whoever is signed in now.
- "Done" pushes: a DONE/FAILED turn stamps `Session.finish_push_due_at`; the next enqueue clears it; the 15 s tick drains due ones (`send_due_session_pushes`, one sender via a conditional UPDATE) after re-checking the session is not busy, archived or blocked. CANCELLED/MISSED never push. Who is pushed: `_finish_audience`, and `chat-sessions.md` § Push.

## Embedded widget (`apps/embedding/embed_api.py`, mounted at `/api/embed`)
The host-facing contract is `embedding-a-canopy-agent.md`; internals in `embedding-internals.md`.
- Routes that answer for a host (`/agents`, `/default-agent`, `/sessions/{id}/agent-memory`) need a delegated token (`_acting_app` reads it from the token, never a path, query or body; 403 otherwise). A site acting for a person may show agent memory but never change it, and may set only a preferred agent it already offers that person (a person's account only).
- **`POST /api/embed/token` is browser-session only** (`embed_self_token`): a header token, delegated app, MCP or machine session gets 403, so a site's token cannot mint itself a fresh one for canopy's own app. Rate-limited per user. The ID-JAG/host-grant behaviour: [embedding-reference.md §11](embedding-reference.md#canopy-web-as-a-host-of-its-own-mcp-agents-act-as-you-on-canopys-pages).
- **Host-grant routes** (`/api/embed/host-grant…`) live in `apps/host_grants/grants_api.py`, whose module docstring states the rule: the panel's token proves nothing about the person (the framing site holds it); only a passkey assertion signed over canopy's origin confirms the grant, and a contact holds none.
- `POST /api/embed/ws-ticket` trades a delegated token for a single-use socket ticket; any other credential is 400.

## Mail (`apps/mail`) — workspace email domains
Product tier, removable ([mail.md](mail.md)). Router `apps/mail/api.py` (module comment states what `MAIL_ENABLED` off refuses); SES webhooks verified in `mail/sns.py`.
- **Domains and routes** (`domains.py`). A domain name is owned by one workspace anywhere (409); a holder still `pending` past `MAIL_PENDING_DOMAIN_TTL_DAYS` is released only if SES confirms it never verified (`_release`). Route writes are `integrations`. The catch-all, `postmaster`, `abuse`, `hostmaster`, `webmaster` and `security` addresses are the domain's own workspace's (`_OWNER_ONLY`); on a shared domain addresses are first come, first served. A forward goes only to a member of the workspace; the catch-all cannot belong to an agent (422). An `auto` route cannot be deleted (409), only disabled. Removing a domain deletes its routes and SES identity but keeps threads and messages.
- **Sign-in domains.** `PATCH` with `sign_in` adds the domain to the workspace's `access_request_domains` and is owner-only and requires verified DNS (`api._set_sign_in`): DKIM verification is the proof that the workspace controls who holds addresses there.
- **Sharing** a domain with another workspace (and its descendants) is `superuser` only; the shared workspace sees only its own routes and send cap, and loses its routes' effect when the share is removed (`domains.route_is_live`).
- **Who reads what.** A thread kept from a forward route belongs to its destination alone: `_visible` returns it to its owner only (404 for everyone else, admins included), and a list without `forwarded=true` never includes anyone's. A reply on one goes out as the caller's own address only (`_reply_from`). Agent mail needs FULL on the agent (`_agent_full`, `turn_context.for_asker`) for reply, send, state change, delete and empty-folder; reads are `member`. Delete for good works only from Trash or Spam (409).
- **Outbound rules.** A reply with no `to` goes to the newest inbound message's Reply-To only if every Reply-To address is on the sender's own domain or a subdomain (Reply-To is unauthenticated), else to its sender (`_reply_recipients`). A turn scoped to one grantor may write to that person alone (403, `_check_scoped_recipients`). Sends enforce the domain's status, suspension and `daily_send_cap` under a row lock (`agent_mail.send`); a send as an agent names one of that agent's own live addresses (422 otherwise); a person with no `agent` sends only from their own exact forwarding addresses, never the catch-all.
- `GET /api/mail/resolve` answers `ses` only if the caller is a member of the address's or thread's workspace, else 404 (the canopy CLI then uses Gmail).
- **SNS endpoints** (`/api/mail/ses/inbound|events/`) are `auth=None`, allowlisted in `apps/common/middleware.py`, and verify signature and topic ARN before reading the body: any verification failure is 404; a transient failure (cert fetch, DB) is 500 so SNS retries; a deterministic failure is acknowledged 200 so a poisoned message cannot loop.
- Mailbox size cap and eviction: [mail.md](mail.md) § Mailbox cap.
