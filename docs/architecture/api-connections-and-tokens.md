# API: connections, tokens and passkeys

Routes for OAuth connections (and server-held calls), personal access tokens, passkeys and step-up, and the debug-access mint. Part of the [api surface](api-surface.md) topic; the index there lists every part.

## Connections (`apps/connections`, mounted at `/api/connections`, `/api/agents`, `/api/me/connections`, `/api/workspaces`, `/api/harness`)
Connections sealed to their owner ([`vault-connections.md`](vault-connections.md) § OAuth connections are sealed to their owner). The browser legs are bare views, above. A connection is owned by one person or one agent and goes through one workspace's app. canopy-web holds no readable token: no response carries a token, and a client secret appears only in a material response to an authenticated machine. A machine route (marked *device proof*) also needs a DPoP proof by an approved, ECDH-ready key of the caller's own runner or enrolled computer (401 `device_proof_required`; 403 `machine_not_enrolled`: "Enroll this computer: canopy vault device --enroll").
Every 4xx/5xx below is problem+json with `error` set to a stable code, mapped in one place (`apps/connections/problems.py`): 409 `not_configured`, `not_connected`, `needs_reconnect`, `ambiguous`, `insufficient_scope`, `wrong_account`, `app_locked`, `no_vault_key`, `owner_changed`, `revoking`, `waiting`; 400 `invalid_app`; 502 `provider_error`; 503 `provider_unavailable`; the wire refusals named per route.
- `DELETE /api/connections/temporary/{id}` — Self (someone else's is 404). End short-lived access (`vault-connections.md` § Lending for an hour) and revoke it at the provider: `{outcome: revoked | ended}`, `ended` when the provider could not be reached; it is gone from canopy-web either way, and needs no passkey.
- `GET /api/harness/runners/{rid}/turns/{tid}/connections/{provider}/temporary` — Runner holding the turn. The access token of the person who started the turn (`{access_token, expires_at, account_label}`), 404 for anyone else's turn or when they have none. `GET …/turns/{tid}/connections` names these in `temporary`.
- `GET /api/connections/` — Self. `{providers: [...], connections: [...], temporary: [...]}` (`temporary`: `{id, provider, workspace, agent, account_label, expires_at}` while each lasts, never the token): one row per (workspace the caller can read with the provider set up) and the caller's own connections. A connection carries `id` (uuid), `state` (`unshared` \| `active` \| `revoking`; a revoking one is not listed), `workspace`, `account_label`, `instance_url`, `scopes`, `needs_reconnect`, `usable`, `missing_scopes`, `expires_at` and `owner_turns_only` (the limits of a lend, `vault.md` § Lending for a while; a connection with either is never canopy-web's), `last_used_at`, `connected_by_email`, and the sharing view: `statement` (`{version, agents: [slug], my_computers: [jkt], endorsers: [jkt]}`), `holders` (runners holding a copy), `waiting` (`[{agent, runner}]` machines allowed but not yet given a copy), `unreachable` (`[{agent, reason}]` agents in the statement no machine can receive it for; `reason` `unvouched` \| `no_machine` \| `lapsed`), `owner_key_replaced` (sealed to a vault key since replaced) and `my_machines` (`[{jkt, name, fingerprint}]`). Never calls the provider.
- `GET /api/workspaces/{workspace}/connection-apps` — workspace `integrations` role. `{apps: [...]}`, one row per registered provider: set-up state, `client_id`, `has_secret` (never the secret; false when the stored one can no longer be decrypted), `options`, `scopes`, the provider's `option_fields` / `scope_choices` / `locked_options` (the options that, like `client_id`, cannot change while connections exist), `connection_count`, and the absolute `callback_url` to register. operationId `list_connection_apps`.
- `PUT /api/workspaces/{workspace}/connection-apps/{provider}` — `integrations` role, an audited setting, behind a passkey step-up from a browser. Creates or updates the app: `scopes` is replaced in full, `options` merged over the stored ones, a blank `client_secret` keeps the stored one (a new `client_id` needs its secret). 400 `invalid_app` (also a blank `client_secret` when the stored one cannot be decrypted); 422 a `client_id` over 255 or a `client_secret` over 4096 characters; 409 `app_locked` while connections exist and `client_id` or a locked option changes (the detail names which). Adding a scope leaves existing connections as they are: each lists it in `missing_scopes`. Not an MCP tool (it carries the secret). operationId `configure_connection_app`.
- `DELETE /api/workspaces/{workspace}/connection-apps/{provider}` — same gate. 204, also when none exists. Disconnects the app's connections first (revoking each; agents they were shared with lose them, recorded as `grant_revoked`). Not an MCP tool (it disconnects everyone's connections). operationId `remove_connection_app`. A workspace cannot be deleted while it has apps: `DELETE /api/workspaces/{slug}/` answers 409 saying to remove them first.
- `POST /api/connections/{id}/server-use` `{on: false}` — Self (mine, or an agent's I administer; anyone else's id is 404), an audited setting. Stops canopy-web using the connection: it removes itself from both stored envelopes, no passkey, no body signed. Already off changes nothing. Answers the `ConnectionOut`. 422 `use_share` when `on` is true (turning it on is part of the signed statement, on the Share screen); 409 `needs_share` when a statement exists (removing canopy-web then needs a new signed statement); 409 `revoking`. `ConnectionOut` carries `server_use` (the switch), `server_reachable` (true: canopy-web can open the stored sign-in now; false: it can't, off or sealed without it; null: the switch is on and the key can't be read right now, nothing needs doing; `share_state.server.reachable` says the same) and `provider_calls` (the switch is shown only when true: canopy-web calls this provider, the connection is not lent with limits, and it has a key set up or the switch is already on; `share_state.server.provider_calls` likewise, and the Share screen offers no canopy-web box without it). operationId `set_server_use`.
- `POST /api/connections/{provider}/request` `{method, path, query?, body?, surface, as?, operation_id?}` — a screen's Salesforce call, through the signed-in person's session only (PAT or OAuth token: 403 `session_required`). Answers the provider's `status` and JSON body, never its headers. Refusals are problems with a sentence in `detail` and `error` one of `not_connected`, `server_use_off`, `ambiguous`, `not_declared`, `not_allowed`, `provider_not_supported`, `needs_approval`, `needs_operation`, `rate_limited`, `session_ended`, `request_too_large`, `response_too_large`, `response_unreadable`, `provider_unavailable`. Rules: [`vault-connections.md`](vault-connections.md) § Calls from screens.
- `POST /api/connections/operations` `{surface}` — a lease for the writes one screen declared: `{operation_id, expires_at, hard_limit_at, writes}`. One click opens up to 10 minutes and 500 writes within what the screen declared, for this person, this screen and revision; it ends 120 seconds after its last write. Session only, 429 `rate_limited` past 60 a minute.
- `GET /api/connections/{id}/surface-shares` · `GET …/surface-shares/preview?kind=&ref=` · `POST …/surface-shares` `{kind, ref, expected_reads, expected_writes}` · `DELETE …/surface-shares/{share_id}` — the projects and apps whose screens may use an agent's connection (agent admins; anyone else's id 404, a person's own connection 422 `not_shareable`). The list gives each share's approved and pending lines and `needs_approval`; the preview gives the lines declared now. `POST` needs a fresh passkey at a browser (a token is 403 `browser_session_required`) and 409 `declaration_changed` when the lines are not those previewed; `DELETE` needs none (204).
- `GET /api/connections/{id}/share` — Self; only the person whose vault key it is sealed to (403 `not_the_owner_key`; 409 `revoking`). What the owner's browser needs to share it: both sealed envelopes with their writer signatures and digests, the stored statement and its signature, the owner's key, `owner_agent`, every machine it could be sealed to (`candidates`, each with the agent that admits it or `mine`), the `endorsements` to check them by (including those covering the machine that wrote each envelope), the person keys to offer as `endorsers`, and the agents the owner may lend it to.
- `PUT /api/connections/{id}/share` — Self, an audited setting, behind a passkey step-up from a browser. `{statement, sig, by_jkt, sealed, sealed_sig, access_sealed?, access_sig?, expect}`: the owner's signed grant statement and the envelopes re-sealed to the machines it allows; the connection becomes `active`. canopy-web opens and signs nothing to do this, and can open the envelopes afterwards only if the statement names it (`canopy_web`). 403 `not_the_owner_key` / `not_an_admin`; 409 `statement_stale` (the version must go forward) / `zk_value_changed` (`expect` is not what is stored) / `revoking`; 422 `bad_statement`, `bad_signature`, `agent_outside_workspace`, `not_your_machine`, `statement_missing_owner_agent`, `foreign_reader` (sealed to someone the statement and `recipients` do not allow), `bad_writer_sig`, `bad_canopy_web` (the statement names canopy-web and this is not its current key, this deployment does not accept it, or the connection is lent with limits). Only the connector can change who uses it. operationId `share_connection`.
- `DELETE /api/connections/{id}` — Self, an audited setting. `{outcome, machine_revokes}`: `revoked` (canopy-web's own key ended it at the provider; the row is gone); `revoking` (it will be revoked at the provider, then deleted: by a cloud box that holds it when `machine_revokes`, else by canopy-web's retries); or `deleted` (the row went without a revoke: no cloud box heard from in the last 15 minutes holds it or could accept its envelope and canopy-web can't, or another connection of that account still needs the sign-in). Someone else's id is 404, not 403.
- `GET /api/agents/{slug}/connections` — Agent admin. The agent's own connections plus ones lent to it (`granted_from` names the owning agent's slug or the person), each in the shape above, with `usable` (its own: false once it is no longer in the connection's `workspace`; a lent one: false once the grant is out of force) and `missing_scopes`. A lent row leaves its owner's computers out of everything it lists.
- `DELETE /api/agents/{slug}/connections/{id}` — Agent admin, an audited setting; from a browser behind a passkey step-up (a token is let through). `{outcome, machine_revokes}`, as for a person's. Lending is route `PUT …/share`; the earlier `PUT|DELETE …/grants/{other_slug}` and `POST /api/me/connections/{provider}/token` no longer exist.
- `GET /api/me/connections/{provider}/material?workspace=` — Self, a person's own computer: a **plain personal access token over REST** (403 `token_route_needs_pat` for a browser session, an MCP call, a connector token or a caller token) plus *device proof* by one of the caller's own enrolled computers. `ConnectionMaterialOut`: `id`, `binding` (`connection:<uuid>`), `account_id`, `account_label`, both envelopes (`sealed`, `sealed_sig`, `sealed_digest`, `access_sealed`, `access_sig`, `access_expires_at`), the signed `statement` and `statement_sig`, `owner {user_id, public_jwk}`, `endorsements`, `recipients`, `app {client_id, client_secret, options}`, `lease {mine, ttl_seconds}` and `rotates_refresh_token`. No token. 409 `not_connected` (none, not shared yet, or being disconnected), `needs_reconnect`, `ambiguous` (lists `workspaces`), `waiting` (this computer may use it but holds no copy yet); 403 `not_on_my_computers` ("Turn on Use on my computers … in Settings → Connections"). Not an MCP tool.
- `POST /api/me/connections/{id}/refresh-lease` · `DELETE …/refresh-lease/{lease_id}` · `PUT /api/me/connections/{id}/sealed` · `POST …/reconnect-required` — the same lease, write-back and dead-token report as a runner's, below, for the caller's own connection from an enrolled, listed computer. Same gate as the material route.
- `GET /api/harness/runners/{runner_id}/turns/{turn_id}/connections` — runner protocol (not an MCP tool), for a turn this runner is executing (else 404, and always for a caller's confined turn; 409 `no_agent`). `{providers: [...]}`: the provider keys the turn's AGENT has a connection for that is shared, its own or one lent to it, sorted — usually empty. No token.
- `GET /api/harness/runners/{runner_id}/turns/{turn_id}/connections/{provider}` — runner protocol, *device proof*, for a turn this runner holds (404 otherwise, and for a caller's confined turn or an unknown provider). The same `ConnectionMaterialOut` for the connection the turn's AGENT uses (its own, else one lent to it, never the person's who started the turn), plus `agent_id` and `agent_slug`: which agent the answer is for. 409 `not_connected` (also not shared yet, being disconnected, or this box no longer serves an agent it is lent to), `needs_reconnect`, `waiting`, `ambiguous`, `no_agent`. Each turn's reads are one `connections.token_issued` Event naming the runner; there is no `connection-token` route.
- `POST /api/harness/runners/{runner_id}/connections/{id}/refresh-lease` · `DELETE …/refresh-lease/{lease_id}` — runner protocol, *device proof*. Take or release the one refresh lease: `{lease_id?}` → `{lease_id, ttl_seconds: 60, expires_at}`; 409 `lease_held` with `retry_after`. A box the connection is not in force for is refused as `not_connected`.
- `PUT /api/harness/runners/{runner_id}/connections/{id}/sealed` — runner protocol, *device proof*. Write back a refresh: `{lease_id, sealed?, sealed_sig?, access_sealed, access_sig, access_expires_at, expect, rotated}` → `{sealed_digest}`. `sealed` is sent exactly when the refresh token rotated. A write-back on an expired lease is accepted if nobody took the lease since. 409 `lease_lost`, `zk_value_changed`, `revoking` (nothing stored); 422 `foreign_reader`, `zk_rewrap_required`, `bad_writer_sig`.
- `POST /api/harness/runners/{runner_id}/connections/{id}/reconnect-required` — runner protocol, *device proof*. `{lease_id, error, detail?}` → 204: the provider answered `invalid_grant`, so the connection is marked `needs_reconnect` and the lease ends (409 `lease_lost`). `detail` is the provider's description, scrubbed by the box, and is recorded.
- `GET /api/harness/runners/{runner_id}/vault-keeper/connections` · `PUT …/vault-keeper/connections/{id}` — runner protocol, a cloud box's keeper. The work (each connection the box holds that is `active` with machines still waiting, or `revoking`; the box builds the paths itself) and a re-seal `{sealed, sealed_sig, access_sealed, access_sig, expect}` → `{machines}`. 403 `zk_not_a_holder`; 409 `zk_value_changed`, `revoking`; 422 `foreign_reader`, `zk_rewrap_required`, `bad_writer_sig`.
- `POST /api/harness/runners/{runner_id}/connections/{id}/revoked` — runner protocol, *device proof*. `{revoked: bool, error: ""}` → 204 and the row is deleted. 403 `zk_not_a_holder`; 409 `not_revoking`.

## Personal Access Tokens (`apps/tokens`)
- `GET /api/tokens/` — my tokens (no raw values; OAuth-minted tokens omitted), each with `last_used_at` and `last_used_client` (the User-Agent of its last REST call or socket — a runner sends its host). A revoked token also stops any socket it opened: `RunnerConsumer` re-checks the credential on every frame (`apps/realtime/channels_auth.py::still_signed_in`) and closes 4001. `POST /api/tokens/` — mint (raw returned once). `DELETE /api/tokens/{id}/` — revoke (mine only; another user's 404s).
- Raw values are sha256-hashed at creation and never stored; a new one starts `cpat_` (older ones are 43 bare characters and still work — `tenancy.md` § Users). Send `Authorization: Bearer <raw>`; `apps.tokens.middleware.BearerTokenAuthMiddleware` resolves it to `request.user`. Bootstrap: `uv run python manage.py create_token --email <email> --label "<label>" --create-user`.
- `GET /api/me/delegated-credentials/` — the credentials from my own accounts I delegated to agents: agent, provider and account, which machines can open each (only those), what the provider said, whether it is in force (I am still the agent's admin). Never the value. By person, not per organisation, like a token. `DELETE /api/me/delegated-credentials/{id}` — withdraw it from the agent's vault (mine only; audited as a setting). See [vault.md § Whose account an entry is](vault.md#whose-account-an-entry-is).
- `GET /api/me/host-grants/` — my live act-as-you permissions (host grants), one row per page (`host_grants.live_for`): site, agent, scope, until. By person, not per organisation: it is my own credential, like a token, and a site in a workspace I am not in can hold one for me. `DELETE /api/me/host-grants/{id}` — stop that page's permission at once (mine only; 404 otherwise; audited as a setting). `GET /api/me/host-grants/{id}` — one of my unexpired permissions, confirmed or still waiting. `POST /api/me/host-grants/{id}/confirm/begin` · `…/confirm/finish` — confirm a page's waiting permission in my browser, for a panel whose frame cannot use a passkey (the Runner app opens `/confirm/page-permission/<id>`): the same confirm as the panel's (`grants_api._confirm`), on my own browser session (a token or token-minted session → 403 `browser_session_required`; another person's grant → 404); the panel sees it on its next read. Mechanics: [embedding-internals.md § Act-as-you permissions](embedding-internals.md#act-as-you-permissions-host-grants-when-which-and-stop).
- `/api/me/act-as-requests/` — an agent acting as the person who started its turn, on canopy-web (`apps/harness/api_act_as.py`; [access-confinement-and-act-as.md § Acting as the person on canopy-web](access-confinement-and-act-as.md#acting-as-the-person-on-canopy-web-act-as-you-in-your-own-turn)). **The agent**, with its turn's own login (a session-scoped one on a laptop): `POST` `{reason (≤500), scope: read|write|either}` → 201 `{id, status: "pending", approve_url, expires_at}` (the request lapses at `expires_at`, 30 minutes, surviving the turn while its conversation is the person's; 403 saying why when the turn has no eligible asker or a stored token asks; 409 while one from this conversation, or this turn outside one, waits); `GET …/{id}` → `{id, status: pending|approved|declined|expired|stopped, scope (read|write once approved), expires_at (pending: the request's deadline; approved: the permission's end), …}` plus `token` in the FIRST agent read of a live approval only (hash stored; later reads omit it). The login that asked, or any later turn login of the same agent in the same conversation for the same person, reads it — 404 otherwise; `GET /api/me/act-as-requests/` with a turn login lists that agent's waiting and live requests in this conversation (no tokens); `POST …/{id}/stop`. **The person**: `GET /api/me/act-as-requests/` (waiting and live, with the reason), `GET …/{id}`, `POST …/{id}/approve/begin` + `…/approve/finish` `{credential, scope: read|write}` (a WebAuthn assertion begun for this request; browser only, every token refused; 409 when it is no longer pending), `POST …/{id}/decline` (browser only), `POST …/{id}/stop`. The `cact_` token then signs in as the person on REST and MCP for 30 minutes from the touch while the turn runs or its conversation is still the person's, `read` → GET routes only, never the routes `act_as.EXCLUDED_*` lists; every request is a call-log row (`acting_agent`, `act_as_grant`).
- `GET /api/tokens/github` — my GitHub App connection (never calls GitHub). `DELETE /api/tokens/github` — forget my grant (canopy's copy only; idempotent 204). `GET /api/tokens/github/installations` — live list of accounts/orgs the app is installed on (the create-agent owner picker); 409 when the grant is unusable (reconnect).

## Passkeys + step-up (`apps/passkeys`, mounted at `/api/passkeys`)
WebAuthn (py_webauthn) passkeys as a SECOND factor, never a sign-in. Every route touches only the caller's own passkeys; every ceremony needs a person at a browser (a token, MCP call or token-minted session gets 403 `browser_session_required`). RP id = the browser's host unless `PASSKEY_RP_ID`/`PASSKEY_ORIGINS` pin it.
- `GET /api/passkeys/` — my passkeys (label, created, last used, synced or device-bound). `DELETE /api/passkeys/{id}` — needs a fresh step-up.
- `POST /api/passkeys/register/begin` → `{options}` for `navigator.credentials.create()`; `POST …/register/finish {credential, label}` → 201. The FIRST passkey needs only a signed-in session (bootstrap); a second needs a step-up with one already held. Registration requires user verification and opens a step-up window.
- `GET /api/passkeys/step-up` — `{active, until, has_passkey, browser, window_seconds}`. `POST …/step-up/begin` → `{options}` for `navigator.credentials.get()` (409 `no_passkey` when none); `POST …/step-up/finish {credential}` verifies against one of the CALLER's passkeys and sets the session's step-up for 5 minutes.
- **The gate other routes use:** `apps.passkeys.stepup.require_recent_step_up(request)` → 403 problem+json with top-level `error: "step_up_required"`, `has_passkey`, `register_url`; the SPA's API client answers it with a passkey prompt and retries (`frontend/src/auth/stepUp.ts`). Each route that needs it says so, twice: it calls the gate after its own 404/403 checks, and its `@gate(..., step_up=True)` declares it. A route whose request or response carries a secret-named field (`SECRET_FIELDS` in `tests/test_every_route_declares_its_gate.py`) must declare `step_up=True` or `step_up="<why not>"` (runner protocol, a credential shown once to its creator, ciphertext only…), and CI checks the declaration against the view's code.

## Debug access (`apps/tokens/mint_session.py`; `is_machine` in `apps/common/views_debug`)
- `POST /api/debug/mint-session/` — bare view: an authenticated caller (in practice the macOS menubar with its runner PAT) mints a short-lived session cookie (`{ttl_seconds}`, clamped 60s–1w; returns cookie + curl example). A minted session counts as a machine (`is_machine`), so the MCP and HCP OAuth consent pages refuse it.
