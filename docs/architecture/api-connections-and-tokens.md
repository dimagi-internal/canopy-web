# API: connections, tokens and passkeys

Rules that cross the routes for OAuth connections, personal access tokens, passkeys and step-up, and the debug-access mint. Part of the [api surface](api-surface.md) topic. Each route's method, path, fields and status codes are its handler's signature and docstring in the router file named below, and `/api/openapi.json`; this page keeps only what those do not say.

## Connections (`apps/connections`, mounted at `/api/connections`, `/api/agents`, `/api/me/connections`, `/api/workspaces`, `/api/harness`)
Read first: [`vault-connections.md`](vault-connections.md) § OAuth connections are sealed to their owner (what is sealed to whom, the share statement, lending, calls from screens). Routers: `apps/connections/api.py` (a person's `/connections`, an agent's `/agents/{slug}/connections`, a person's CLI `/me/connections`, a workspace's `/workspaces/{ws}/connection-apps`), `api_turns.py` and `api_runner.py` (the runner protocol under `/harness`), `views.py` (the browser legs of connecting, bare views).
- **canopy-web holds no readable token.** No response carries a token. The exceptions are the app's `client_secret`, inside a material response to an authenticated machine (`ConnectionMaterialOut`), and the short-lived token of the person who started a turn (`api_turns.py::turn_temporary_token`).
- **Visibility is 404, not 403.** Another person's or agent's connection id is a 404 so ids cannot be probed (`api.py::_visible`, `disconnect_mine`, `_shareable`). The one deliberate 403 is `get_share_state`: someone who can see it but is not the key's owner gets `not_the_owner_key`.
- **Sharing is the owner's act.** `share_connection` checks the signer holds the vault key the connection is sealed to (403 `not_the_owner_key`); an agent's connection is managed by the agent's admins (`agent-admin` gate). A person's own connection can never serve other people's screens (`_shareable`: 422 `not_shareable`).
- **Passkey step-up is asymmetric on purpose.** Taking access away needs none: `end_temporary`, `set_server_use` (off only; turning it on is part of the signed statement, 422 `use_share`), `stop_surface_share`, `disconnect_mine`. Widening it needs one: `approve_surface_share` always (a token is refused 403 `browser_session_required`, so whoever wrote a screen cannot approve it with a token alone); `share_connection`, `disconnect_agent_connection`, `configure_connection_app`, `remove_connection_app` require it of a browser and let a token through. Each calls `stepup.require_recent_step_up` after its own visibility check, so a non-admin gets 404, never a prompt.
- **Machine routes are three families, each with its own gate.** (1) A person's CLI (`me_router`): a plain personal access token over REST (`api.py::_plain_pat`: not a browser session, an MCP call, a connector token or a caller token; 403 `token_route_needs_pat`) plus a DPoP device proof by one of the caller's own enrolled computers (`proofs.proving_machine`), and the connection must list that computer (`not_on_my_computers`). (2) A runner holding a claimed turn (`api_turns.py::_turn_agent`): runner token, device proof, `runner_may_hold_agent`, and never a caller's confined turn (404). The material is the turn's AGENT's connection, never the person who started the turn. (3) A box's lease, write-back and revoke confirmation (`api_runner.py::_box_connection`), which need the box to serve an agent the connection is in force for now (`tokens.admits_runner`); its keeper routes instead need the box to HOLD it, because a revoking row is in force for nobody yet its holders revoke it (`keeper.py`).
- **One refresh lease per connection.** A machine takes it (`tokens.take_lease`, 60 s) before refreshing at the provider and writes the result back against the digest it read (`tokens.write_back`); a write-back is refused when the lease was lost or the sealed value changed, and sealed data is checked for foreign readers and writer MACs. The refresh envelope and the access envelope bind to different digests (see the `my_connection_material` docstring).
- **Errors have one mapping.** Every connection refusal is problem+json with a stable `error` code, mapped in `apps/connections/problems.py` (`_PROBLEMS`, `_CALL_PROBLEMS` for a screen's call, `_WIRE_TITLES` for sharing and machine routes). Add a code there, not in a route.
- **A screen's provider call is a session only** (`api.py::request_connection_call`, `open_connection_operation`): a token is 403 `session_required`; the write lease bounds how far a script holding the session can go. Rules: `vault-connections.md` § Calls from screens.
- **A workspace cannot be deleted while it has connection apps.** `ConnectionApp.workspace` is PROTECT and `workspace_delete_hint` is what `apps/workspaces/api.py::delete_workspace`'s 409 tells the admin; removing an app (`services.remove_app`) disconnects every connection made with it first.
- **An app's client id and `locked_options` cannot change while connections exist** (409 `app_locked`, `configure_connection_app`); a new scope leaves existing connections as they are, each listing it in `missing_scopes`.

## Personal Access Tokens (`apps/tokens`)
Routers: `apps/tokens/api.py` (`/api/tokens/`), `apps/tokens/api_me.py` (`/api/me/…` preferences), `apps/github_connect/api.py` (`/api/tokens/github…`, a person's GitHub App connection; the list of installations is live and 409s when the grant is unusable).
- A raw token is sha256-hashed at creation and never stored; a new one starts `cpat_` (older ones are 43 bare characters and still work, [`tenancy.md`](tenancy.md) § Users). `apps.tokens.middleware.BearerTokenAuthMiddleware` resolves `Authorization: Bearer <raw>` to `request.user`. Bootstrap a first token: `manage.py create_token --help`.
- **A limited credential cannot mint a longer-lived one.** `middleware.minting_refusal` allows a browser session and a plain PAT (`MINTING_CREDENTIALS`, an allowlist, so a new token kind is refused until decided) and refuses an hour-long OAuth token or a site's delegated token: they must not buy a never-expiring PAT or a week-long cookie (`api.py::create_token`, `mint_session.py::mint_session`).
- **Revoking a token stops its sockets.** `apps/realtime/consumers.py::RunnerConsumer.receive_json` re-checks the credential on every frame (`channels_auth.still_signed_in`) and closes 4001.
- **Credentials about me are read by person, not per organisation** (I can act on them after leaving the workspace): `apps/agents/api_delegated.py` (credentials I delegated to agents; never the value; withdrawing only stops later turns, so revoke at the provider too), `apps/host_grants/grants_api.py` (my act-as-you permissions on pages; confirming one needs a browser session and a person, never a token). Mechanics: [`vault.md`](vault.md) § Whose account an entry is, [`embedding-internals.md`](embedding-internals.md) § Act-as-you permissions (host grants): when, which, and Stop.
- **Act-as requests** (`apps/harness/api_act_as.py`, mechanics in `apps/harness/act_as.py`; [`access-confinement-and-act-as.md`](access-confinement-and-act-as.md) § Acting as the person on canopy-web): the agent asks with its turn's own login, only the person approves or declines, with a passkey assertion made for that request at a browser (every token refused). The `cact_` token it yields lasts 30 minutes from the touch, is returned once, and never reaches the routes `act_as.EXCLUDED_PREFIXES`, `EXCLUDED_PATTERNS` and `EXCLUDED_TOOLS` list (`route_refusal`).

## Passkeys + step-up (`apps/passkeys`, mounted at `/api/passkeys`)
A passkey is a SECOND factor, never a sign-in. The module docstring of `apps/passkeys/api.py` states who may call what: every route touches only the caller's own passkeys, every ceremony needs a person at a browser (a token, MCP call or token-minted session gets 403 `browser_session_required`; an agent's login or a system account gets `not_a_person`), the FIRST passkey needs only a signed-in session, and any later change to the set (add, delete) needs a fresh step-up with one already held.
- **The gate other routes use:** `apps/passkeys/stepup.py::require_recent_step_up(request)` (403 `step_up_required` with `has_passkey` and `register_url`; the SPA answers it with a passkey prompt and retries, `frontend/src/auth/stepUp.ts`). A step-up lives in the Django session for `STEP_UP_SECONDS`, stamped with its user, and a token can never hold one.
- **Each route that needs it says so twice:** it calls the gate after its own 404/403 checks, and its `@gate(..., step_up=True)` declares it. A route whose request or response carries a secret-named field (`SECRET_FIELDS` in `tests/test_every_route_declares_its_gate.py`) must declare `step_up=True` or `step_up="<why not>"` (runner protocol, a credential shown once to its creator, ciphertext only), and CI checks the declaration against the view's code.

## Debug access (`apps/tokens/mint_session.py`; `is_machine` in `apps/common/views_debug.py`)
`POST /api/debug/mint-session/` is a bare view that turns an authenticated caller (in practice the macOS menubar with its runner PAT) into a session cookie, subject to `minting_refusal` above. A minted session still counts as a machine (`is_machine`): the MCP and HCP OAuth consent pages (`apps/oauth_server/views.py`, `apps/contacts/hcp_oauth_views.py`) refuse it, and `stepup.is_browser` is false for it.
