# API: workspaces

Routes for workspaces: tenancy, members, invites, access requests, parents, vaults, holds, apps and the rest of what a workspace owns. Part of the [api surface](api-surface.md) topic; the index there lists every part.

## Workspaces (`apps/workspaces`) — multi-tenancy
`Workspace` + members (`owner` / `admin` / `editor` / `viewer`) + email invites; workspaces nest (owners of a parent own the children). Gates use `apps/workspaces/permissions.py` (`docs/architecture/roles.md`).
- `POST /api/workspaces/` create · `GET /api/workspaces/` list mine · `GET /api/workspaces/{slug}/` (member) · `DELETE /api/workspaces/{slug}/` (owner; only an empty workspace — never one that still owns agents).
- `PUT /api/workspaces/{slug}/parent` — move in the tree (`parent: null` = root). Owner of both the moved workspace and the new parent; a cycle is 422. Someone who owns it only through its parent gets 409 making it a root, or moving it where a current owner would lose it.
- `GET /api/workspaces/{slug}/members/` (member) — includes parent-workspace owners with `inherited: true` (changed on the parent).
- `POST /api/workspaces/{slug}/members/` `{user_id, role}` → 201 `MemberOut` — add someone ALREADY in this workspace's tree, directly, no invite (admin or owner; a role you may grant, else 403). The person must be a member, directly or by inheritance, of a workspace the caller is in under the same root, else 404 — never an arbitrary user id; 409 if they already hold a direct row here (PATCH instead) (`services.add_tree_member`).
- `GET /api/workspaces/{slug}/member-tree` (member) — `{root, workspaces: [{slug, display_name, parent, depth, my_role, can_manage}], people: [{user_id, email, cells: {slug: {role, inherited, inherited_from}}}]}`: `slug` and the workspaces below it the caller is in (`services.subtree`), in tree order, and everyone in any of them from `services.effective_memberships` (a missing slug = not a member). The page `/w/:ws/settings/member-tree`.
- `PATCH|DELETE /api/workspaces/{slug}/members/{user_id}/` — change role / remove (admin or owner; an admin manages only roles strictly below its own). Role change is idempotent; demoting or removing the last owner is 400 (`services.is_last_owner`).
- `POST /api/workspaces/{slug}/invites/` (admin or owner) — emails the accept link through SES (`apps/common/email.py`); `email_status` (`sent` / `throttled` / `not_configured` / `failed`) says whether it went out, and the link in `token` works either way. Inviting an address with an outstanding invite returns that invite and re-sends, at most once a minute (its token is unchanged).
- `GET /api/workspaces/{slug}/invites/` (member) — `token` is filled only for owners.
- `POST /api/workspaces/{slug}/invites/{invite_id}/revoke` (admin or owner).
- `POST /api/workspaces/{slug}/invites/{invite_id}/reissue` (admin or owner) — new token + fresh 14-day expiry, emailed; the old link dies. Works on an expired invite; 410 on accepted/revoked; 429 if emailed under a minute ago (checked before rotating).
- `GET /api/workspaces/invites/{token}/preview` — `auth=None`, minimal disclosure (a dead token reveals only that it is dead). Drives `/invite/:token`. `POST /api/workspaces/invites/{token}/accept` — accept. An invite's address matches the signed-in email by `invites.mailbox_key`: case-insensitive, and a Gmail address under any dot spelling (Google signs a person in under the spelling the account was created with); never plus-addressing or other providers' dots.
- `GET /api/workspaces/invites/mine` (signed in) — your own live invites with their links, newest first; Home lists them. Listing joins nothing.
- **Access requests** (`docs/architecture/access.md` → "Getting into a workspace"; nothing joins automatically): `GET /api/workspaces/requestable` — workspaces whose server-only `access_request_domains` include the caller's email domain and they are not in, with their open request. `POST /api/workspaces/{slug}/access-requests` (`{note?}`) — emails every admin/owner; idempotent while pending (200); with `auto_approve_role` set it is approved at once; nonexistent and not-your-domain are the same 404; 409 if already a member. `GET …/access-requests[/{id}]` (admin or owner; `?status=`). `POST …/{id}/approve` (`{role}`: viewer/editor/admin, below your own unless owner → else 403) · `POST …/{id}/deny` (`{reason}`); both 409 once decided and email the requester. `PUT /api/workspaces/{slug}/access-settings` (owner) — `auto_approve_role` `""` / `viewer` / `editor`.
- `GET|PUT /api/workspaces/{slug}/runner-order` — the workspace's default runner order (index = rank): routes agentless repo turns, and is the default of every agent here, and every workspace below, with no order of its own (`harness.routing.inherited_orders`). Read: member. Write: admin or owner (`runners.route`); each runner must be able to serve this workspace, else 422 (as for unknown/retired). See `docs/architecture/runners.md`.
- `GET /api/workspaces/{slug}/runner-topology` — admin+ (`logs.read`), checked on every descendant too. This workspace and its descendants in tree order: agents, every `RunnerAssignment` row (default list + rules), and the runners named or living in the tree; `can_claim: false` on a route means the runner's owner is not in the agent's workspace, or the runner is directed-only (its row carries `directed: true`; an agent following an order that lists it names it in `follows.directed`). Computed (`apps/harness/topology.py`). UI: Settings → Topology (map + `/topology/runners`).
- `GET /api/workspaces/{slug}/health` — same gate. Every workspace in the tree (depth, shared vault + where it is inherited from) and every agent: owner, `can_fix` (`Agent.is_admin`), properties, `vault` (`vault_health`: per-ref stored/literal/local/missing, `machines_waiting`), `steps` (exactly `setup_steps`), `left`, sessions, projects and tasks; `runners` (the runner topology's rows, with `code_current` and `problems`); totals. `?setup=false` leaves `vault`, `steps`, `left` and the totals counted from them null; `GET …/health/setup?agents=a,b` (≤25, tree agents only) returns just those. `apps/agents/health.py`. UI: `/w/:ws/health`.
- `GET /api/workspaces/{slug}/analytics?days=30&tree=true` — same gate. Daily series, totals, per-agent, per-repository and per-person tables (one aggregation), no cost, over `Activity` + `TurnUsage` only (`apps/events/analytics.py`, `docs/architecture/analytics.md`). UI: `/w/:ws/analytics`.
- `GET /api/workspaces/{slug}/network?days=30&tree=true` — same gate. People, contacts and agents linked to the threads they wrote in (a chat, a bound Slack thread being one, or an email thread), each thread to its answering agent; a chat's title only where the session ACL lets the caller open it; at most `analytics.MAX_THREADS` threads, shared ones first (`analytics.network`, `docs/architecture/analytics.md` § Network). UI: `/w/:ws/network`.
- `GET /api/harness/runners/{id}/usage-scope` · `POST …/usage` (the runner) — the box's usage report: the repos it scans, and per Claude session per UTC day tokens, no content (`apps/harness/api_runners_protocol.py`, stored as `SessionUsage` in `apps/events/models.py`); a session canopy has no record of is dropped. canopy never asks a box for a session it was not sent.
- `PUT /api/harness/runners/{id}/slash-commands` (the runner) — the slash commands its sessions can run, `{commands: [{name, description, args_hint, source}]}`, replacing what was held; sent when the list changes (`canopy_runner/slash_commands.py`). Held on `Runner.slash_commands`, off `RunnerOut`.
- `GET /api/workspaces/{slug}/agent-topology` — same gate. For each ordered agent pair, what the first gets sending the second work with its own login: `access` full/confined/none, `basis` (wire values: owner, workspace-owner, admin, editor, no-interface, profiles, nothing-offered, not-member, no-login), `profiles`: when confined, what it opens: read mode (wire name `read`, or `ask` for an agent's own read mode) or host-site names, `can_grant`/`can_revoke` for this caller; `full_people` per agent. Decided by the predicates a real turn uses. Grant via `PUT /api/agents/{slug}/admins/{user_id}` with the sender's login. UI: `/topology/agents`.
- `GET /api/workspaces/{slug}/retention` (member) · `GET …/retention/preview` (counts only, deletes nothing) · `POST …/retention/rules` · `PUT|DELETE …/retention/rules/{rule_id}` (`retention.manage`, admin+) — content retention rules incl. inherited ones; blank filters match anything, `keep_days` null = forever; 422 on a duplicate filter set or an agent outside the workspace. See [tenancy-session-access-and-retention.md § Content retention](tenancy-session-access-and-retention.md#content-retention-appsretention).
- `GET /api/workspaces/{slug}/admission-rules` (member) · `POST …` · `PATCH|DELETE …/admission-rules/{rule_id}` (`admission.manage`, admin+) — which turns this workspace refuses before they run, with fire counts. At least one condition per rule; an `allow` beats every `reject`; PATCH changes only the sent fields (incl. on/off); a deleted seeded default is not re-seeded. `PUT …/admission-settings` `{sender_notices_enabled}` (`admission.manage`) — whether a rule's automatic reply to a rejected sender is sent (off: recorded, not sent). See `docs/architecture/access-direct-use-and-admission.md` → "Admission rules".
- **Host sites** (`apps/embedding/host_sites_api.py`, rules in `embed_apps.py`; owner): `GET|POST /api/workspaces/{slug}/host-sites`, `PATCH|DELETE …/host-sites/{id}`. `POST`, and a `PATCH` that changes `public_keys`, `jwks_url` or `host_issuer`, need a passkey step-up (a token is refused). `default_agent` (one of the site's `agents`, checked after any `agents` change in the same request; `""` clears) is the agent its panel opens on when neither the page nor the visitor chose one. Each row carries `live_probe` (`{at, ok, step, step_label, reason}`) and `traffic` (`{last_redeemed_at, last_site_call_at, refusals_24h}`).
- `GET /api/sites/agents` — **the site agents API** (`apps/host_grants/api.py`, content `site_agents.py`; `auth=None`, gate `host`). The credential is `Authorization: Bearer <JWT>` signed by the site's own registered key (`assertions.keys_for_app`): `typ` `canopy-site-agents-request+jwt`, `iss` = `sub` = its host-site name (resolved by `embed_apps.resolve_site`: a signed `canopy_workspace` — the workspace slug — selects the tenant, or failing that a signed `canopy_agent`'s workspace; both must agree, else 409 `workspace_mismatch`; neither, between tenants sharing the name, 409 `ambiguous_issuer`), `aud` = the endpoint URL under canopy's identity or public base, ≤ 60 s, single-use `jti`. Refusals 401 (`unknown_issuer`, `bad_signature`, `replayed`, `wrong_audience`, `bad_typ`, …), rate-limited per client and per site. Answer `application/jose`: a compact JWS signed with canopy's client key (`typ` `canopy-site-agents+jwt`, `kid` in `/oauth/jwks.json`), payload `v`, `iss` (client_id), `aud` (site name), `iat`/`exp` (15 min), `version` (sha256 of the canonical `site`+`runner_flags`+`agents`), `site {name, tenant, settings_url}` (`settings_url` = the site's card on the host sites page, `…/settings/host-sites#site-<id>`), `runner_flags [{flag, meaning}]`, `agents`: the site's `AppCredentialAgent`s in its own workspace, each with its entries naming the site in `sites:` (`handles_sensitive` = `data: sensitive`, `sensitive_set_by`/`sensitive_set_at` = who last saved any of the agent's read mode or host-site entries (not per row; see [host-sites.md](host-sites.md)), as `Canopy-Execution` states it), `runners {flags_available, ready_with}` (from `setup.runner_takers`, flags in force), `ready` (an entry for the site AND a runner ready now; no GitHub token is needed — a site turn is confined), `problems` (sentences naming where to fix it) and `problem_links` (`[{text, url}]`, the same sentences each with the URL that fixes it). Verified by `canopy_sdk.site_agents.fetch_site_agents`.
- `POST /api/sites/resources-updated` — **a host site says some of its resources changed** (`apps/host_grants/api.py`, checks in `resources_updated.py`; `auth=None`, gate `host`, kind `action`; not an MCP tool). The credential is `Authorization: Bearer <JWT>` signed by the site's own registered key, resolved exactly as `GET /api/sites/agents`: `typ` `canopy-resources-updated+jwt`, `iss` = `sub` = the site's name, `aud` = this endpoint's URL, ≤ 60 s, single-use `jti`, and `uris` (1–50 resource URIs). The body is ignored. Every View subscribed (`…/apps/{tool_call_id}/subscribe`) to one of those URIs on THIS site gets the socket frame `app.resource_updated` — the URI and its call id, never data; each View re-reads as its viewer. Answer `{notified}`. Refusals 401 (`unknown_issuer`, `bad_signature`, `replayed`, `wrong_audience`, `bad_typ`, …), 400 (`malformed`), 429 (per client, per site). Built and sent by `canopy_sdk.resources.notify_updated`.
- `POST /api/sites/sign-offs` · `GET /api/sites/sign-offs/{id}` — **site sign-offs: a host site asks a person to approve one action with their passkey** (`apps/host_grants/sign_offs_api.py`, rules in `sign_offs.py`, row `tokens.SiteSignOff`; `auth=None`, gate `host`, the ask kind `request`; spec `docs/superpowers/specs/2026-10-27-site-sign-offs-design.md`). Signed by the site's own key, resolved exactly as `GET /api/sites/agents`: `typ` `canopy-sign-off-request+jwt`, `aud` = the exact URL, ≤ 60 s, single-use `jti`; the ask carries `sign_off_request {subject, action {key, title, detail}, site_ref, return_url}`. `return_url` must be https on an origin the site registered (frame origins or JWKS URL), else 422 `bad_return_url`. Who approves is `sign_offs.approvers_for`: a person whose verified address resolves to them and who is a member of the site's workspace (`subject`, 15 min), or one of the workspace's agents by login or mailbox (`agent_admins`: its owner or a person admin, 24 h); anyone else 422 `no_approver`. The ask answers 201 `{id, approve_url, expires_at, approvers}`; the read `{id, state, expires_at, approval}` (`approval` a JWS signed with canopy's client key, `typ` `canopy-sign-off+jwt`, for 10 min after approval, one fixed `jti`; another site's id 404). Built and checked by `canopy_sdk.sign_offs`.
- `POST /api/sites/runner-attestations` — **runner attestations: a host site asks which approved runner made a request** (`apps/host_grants/runner_attestations_api.py`, rules in `runner_attestations.py`; `auth=None`, gate `host`, kind `request`). Signed by the site's own key like the sign-off ask (`aud` = this URL, no `sign_off_request`). The body carries the runner's proof (`kind` `dpop` or `aws-iam`, `proof`, optional `agent`) and the exact `htu` it must be made for: an origin the site registered, ending in a sha256 of the request it vouches for (`canopy_sdk.runner_attestations.bound_url`), so it vouches for that request only; the proof must carry precisely that `htu`, is single-use and fresh within 120 s. Answers `{runner, kind, jkt, agent, serves_agent}` for an ACTIVE device key of a non-retired runner, else 401 `proof_refused` in one wording. Reuses `device_keys.verify_proof` / `aws_iam_proof.verify_caller` with a caller-supplied `htu` check. Built and checked by `canopy_sdk.runner_attestations`.
- `GET /api/sign-offs/{id}` · `POST /api/sign-offs/{id}/approve` · `POST /api/sign-offs/{id}/decline` — **the approver's side** (gate `sign-off-approver`, `sign_offs.may_approve`, asked again at every call; anyone else 404). Approve is a setting, needs a browser, a person and a passkey step-up (a token is 403), and answers the row plus `redirect_url` (the site's `return_url` with `?sign_off=<jws>&id=`); decline answers `redirect_url` with `?declined=`. A decided or expired request is 409 `closed`. Open requests are on their approvers' Home (`apps/host_grants/attention.py`).
- `GET /api/embed/sign-offs/{id}` · `POST /api/embed/sign-offs/{id}/approve/begin` · `POST .../approve/finish` · `POST /api/embed/sign-offs/{id}/decline` — **the same, decided on the site's own page** in canopy's frame (`/embed/sign-off`, the widget's `canopy.signOff`; SDK `{% canopy_sign_off %}`). The frame's delegated token, and only the frame of the site that asked (another site's frame, or a PAT, is 404/403); the person is `sign_offs.may_approve` as above. Approve is a WebAuthn assertion with one of the person's passkeys made in the frame (`begin` an ephemeral credential, slot per request and person; `finish` a setting), as the panel's act-as-you confirm: the token is the site's, the assertion over canopy's origin is the person's. Answers the row only, never the approval: the site reads that with `GET /api/sites/sign-offs/{id}`. 409 `closed` / `no_passkey`.
- `GET /api/workspaces/{slug}/host-sites/{id}/needs` — what the site asks of agents (its signed `site.json`, read beside its `jwks.json` by `apps/host_grants/site_needs.py`: pinned/bounded fetch, verified with the site's keys, cached 10 min, last good shown `stale` for 24 h, else `available: false` + `reason`) and, per allowed agent, `{url, offered, sensitive_data, ready, can_handle_sensitive_data, why_not}` computed from the same `site_agents_content` the site reads — `sensitive_data` is whether the site lets the agent work with its sensitive data; `can_handle_sensitive_data` is `null` when it does not (nothing to meet, no reasons), else whether the agent meets the site's `sensitive_data.requires` and is ready, with `why_not: [{text, url}]` (no host site for the site says `data: sensitive`, no ready runner with the flag, or the agent's other problems, each with the canopy page that fixes it). `pages` (+ scopes) is the site's own description, shown for reference only — canopy neither enforces it nor tells an agent; `not_allowed` = agents the site names that this workspace does not allow on it. Gate `integrations`.
- `GET /api/workspaces/{slug}/host-sites/discover?address=&app_id=` — **Fill from the site** (`apps/host_grants/api.py`, logic `site_needs.discover`; gate `own`, read-only). Finds the site's signed `site.json` from `address` (the document's URL, its JWKS URL, or just the site's address: `…/site.json`, `/.well-known/canopy-site.json`, `…/canopy/site.json`) or, with `app_id`, beside the site's keys / at its first origin; fetched fresh (pinned, https, public addresses, no redirects). Verified with the site's registered keys (`signed_by: registered_keys`) or the keys at the `jwks_url` the document declares (`published_keys`; `registered_keys_verify: false` when registered ones exist and do not verify it); `iss` must be the site's name for `app_id`. Returns `{url, tried, name, site: {origins, jwks_url, issuer, mcp_resource}, signed_by, registered_keys_verify, current, changes}` (`current`/`changes` for `app_id`). 422 with `unreachable`, `no_facts` (no `site` block: SDK < 0.16), `bad_signature`, `bad_issuer`, `keys_unreachable`, `malformed`, `no_address`. Never writes: the owner adopts the values through `POST`/`PATCH …/host-sites` (audited).
- `POST /api/auth/contact-token` resolves the site the same way: the assertion's signed `canopy_workspace` selects the tenant (409 `workspace_mismatch` if `agent_slug` is not one of its agents; 400 `bad_workspace` for a malformed claim), else `agent_slug`'s workspace. The embed shell `/embed/chat` takes `?workspace=` beside `?agent=` (any refusal a 404).
- `POST /api/workspaces/{slug}/host-sites/{id}/test` — **Test connection** (owner; another tenant's site 404s). From canopy's server, returns `{ok, checks: [{name, label, status: pass|fail|skip, detail}], live_probe, live_probe_ok}`: the JWKS (`check_jwks`: reachable, public-only, asymmetric, thumbprint `kid`; RSA only for an assertion-only site) and pasted PEM key types; for a host-grant site, RFC 8414 + 9728 discovery (`check_metadata`) and `check_client` (jwt-bearer with canopy's real client assertion + DPoP and an ID-JAG from a throwaway key: `invalid_grant` = host authenticated canopy, `invalid_client` = it does not accept canopy, 200 = it accepted a grant it never signed). Then the **live probe** (`apps/host_grants/live_probe.py`), folded into `ok`: the host's `canopy_probe_endpoint` signs a real ID-JAG for its probe principal; canopy redeems via `host_grants.redeem` and calls via `host_gateway` — the probe tool succeeds, an out-of-scope tool is refused by the host, and no proof / a stranger's proof / plain bearer are refused. No probe identity → `live_probe_ok: null`. All fetches via `outbound.py`.
