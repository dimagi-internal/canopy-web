# API: workspaces

Rules for the routes a workspace owns: tenancy, members, invites, access requests, runner routing and health reads, retention, admission, and host sites. The routes, params and shapes are in the routers and `/api/openapi.json`; this page keeps what they do not say. Part of the [api surface](api-surface.md) topic.

Start reading at: `apps/workspaces/api.py` (tree, members, invites, access requests), `apps/workspaces/permissions.py` + `gates.py` (roles: [roles.md](roles.md)), `apps/harness/api_workspace_routing.py` (topology, runner order), `apps/agents/api_workspace_health.py` (health, agent topology), `apps/retention/api.py`, `apps/admission/api.py`, `apps/embedding/host_sites_api.py`, `apps/host_grants/` (the signed site APIs).

## Tree, members, invites, access requests (`apps/workspaces/api.py`)
- **Delete** (`delete_workspace`, owner): refused 409, naming what is in the way, while the workspace has child workspaces, agents, or anything else protecting it (project turn history, chat sessions). Memberships and invites cascade.
- **Move** (`set_workspace_parent`): the caller owns both the moved workspace and the new parent; a cycle is 422 (`Workspace.save`). Moving or detaching ends the old parent's inherited ownerships, so someone who owns it only through its parent gets 409 when making it a root, or moving it where a current owner would lose it. `members` lists inherited owners with `inherited: true`; change them on the parent.
- **Who may grant what** (`_require_may_manage`, `permissions.may_manage_member`): below owner, members are managed strictly below your own role, and you never grant your own or a higher role (403). Demoting or removing the last owner is 400 (`services.is_last_owner`).
- **Add without invite** (`add_member` → `services.add_tree_member`): only a person already in this tree and visible to the caller; anyone else is 404, so it is never a way to add an arbitrary user id; 409 if they hold a direct row here.
- **Invites**: `GET …/invites/` shows `token` only to a caller who may manage that invite's role (a pending token is the invite). Re-inviting a pending address returns the same invite and re-sends at most once a minute; `reissue` rotates the token and expiry (old link dies), is checked for the 1-minute throttle BEFORE rotating (429), works on an expired invite, and is 410 on accepted/revoked. `preview` is `auth=None` and a dead token reveals only that it is dead. Accepting matches the signed-in email by `invites.mailbox_key` (case, and Gmail dots only; never plus-addressing or other providers): 403 `email_mismatch`. Nothing joins automatically: `invites.accept_invite` is the only path from an invite to a membership.
- **Access requests** ([access.md](access.md) → "Getting into a workspace"; `access_requests.py`): visible only where the caller's email domain is in the server-only `access_request_domains`; a missing workspace and a not-your-domain one are the same 404 (no tenant probing); idempotent while pending; with `auto_approve_role` set it is approved at once; approve grants a role below your own unless owner (403), both decisions are 409 once made.

## Runner routing and fleet reads (`api_workspace_routing.py`, `apps/agents/api_workspace_health.py`)
- `runner-order` GET is member-readable; PUT is `runners.route` (admin+). It is the default order of every agent here without its own order and of every workspace below without one (`routing.inherited_orders`); each runner must be able to SERVE this workspace (enrolled, its owner an editor or above) or the write is 422. Claim and routing: [runners.md](runners.md), [runner-routing.md](runner-routing.md).
- `runner-topology`, `health`, `health/setup`, `agent-topology`, `analytics`, `network` are `logs.read` (admin+) on the root AND on every descendant (`gates.tree_reader` filters per descendant), so an admin of the root sees every division. `health/setup` takes at most `HEALTH_SETUP_MAX` agents. `can_fix` mirrors `Agent.is_admin`; `agent-topology` is computed by the predicates a real turn uses (grant via `PUT /api/agents/{slug}/admins/{user_id}` with the sender's login). `network` shows a chat's title only where the session ACL lets the caller open it. Analytics read `Activity` + `TurnUsage` only ([analytics.md](analytics.md)).
- Runner-side reports (`api_runners_protocol.py::post_runner_usage`, `api_runners_credentials.py::report_slash_commands`): runner-gated; usage is tokens per session per UTC day with no content, and a session canopy has no record of is dropped; canopy never asks a box for a session it was not sent. Slash commands replace the held list and stay off `RunnerOut`.
- **Retention** and **admission** rules (`apps/retention/api.py`, `apps/admission/api.py`): reads are member-level, writes `retention.manage` / `admission.manage` (admin+). Retention: [tenancy-session-access-and-retention.md](tenancy-session-access-and-retention.md#content-retention-appsretention). Admission: an `allow` rule exempts a turn from every `reject`; a rule needs at least one condition; a deleted seeded default is not re-seeded ([access-direct-use-and-admission.md](access-direct-use-and-admission.md) → "Admission rules").

## Host sites (`apps/embedding/host_sites_api.py`, rules in `embed_apps.py`; deeper: [host-sites.md](host-sites.md))
- **Gates**: list, `test` and `needs` are `integrations` (admin+); connect, change, delete and `discover` are `own`. Another tenant's site is 404 before 403.
- **Passkey step-up** (`stepup.require_recent_step_up`): connecting a site, and a PATCH that changes what it may sign (`public_keys`, `jwks_url`, `host_issuer`; compared as typed by `_changes_signer`), need a person at a browser who just used a passkey; a token is refused (403 `step_up_required`). `asserts_verified_email` is a canopy superuser's decision (trusting a site's email claims is canopy-wide), and changing the signing keys of a trusted site resets it to false.
- **`test`** (`test_host_site`): every URL was typed by a tenant, so all requests go through `host_grants/outbound.py` (https only, no private address space, no redirects, bounded); the settings checks cannot redeem a real grant, the live probe can because the HOST signs it for its own probe principal (`live_probe.py`).
- **`discover`** (`site_needs.discover`) never writes: the owner adopts values through the create/update routes (audited); it requires `iss` to be the site's name for `app_id`.
- **`needs`**: `pages`/scopes are the site's own description for display; canopy neither enforces nor tells an agent. Fail-closed: an unreadable document is `available: false`.

## Signed site APIs (`apps/host_grants/`; `auth=None`, gate `host`: a request signed by the site's own registered key IS the credential)
- **Request rules** (`site_agents.py`, `assertions.py`): `Authorization: Bearer <JWT>` with the site's `typ` for that endpoint, `iss` = `sub` = the host-site name, `aud` = the exact endpoint URL, at most 60 s, single-use `jti` (a cache that cannot record the `jti` reads as a replay: fails closed). Budgets are spent per client before parsing and per site before the signature is checked (`embedding/rate_limit.py`); refusals are 401 (`unknown_issuer`, `bad_signature`, `replayed`, `wrong_audience`, `bad_typ`), 400 `malformed`, 429.
- **Which tenant a name means** (`embed_apps.resolve_site`, the one place a site name becomes a row): a signed `canopy_workspace` selects the tenant, else a signed `canopy_agent`'s workspace; both must agree (409 `workspace_mismatch`); neither, between tenants sharing the name, is 409 `ambiguous_issuer`. `POST /api/auth/contact-token` resolves the same way (400 `bad_workspace` for a malformed claim); the `/embed/chat` shell turns any refusal into a 404.
- `GET /api/sites/agents` (`get_site_agents`, content `site_agents.site_agents_content`): the answer is a JWS signed with canopy's client key (`/oauth/jwks.json`); `ready` needs an entry for the site AND a ready runner (no GitHub token: a site turn is confined); `problems`/`problem_links` name where to fix each gap.
- `POST /api/sites/resources-updated` (`resources_updated.py`): fans an `app.resource_updated` socket frame to Views subscribed to those URIs on THIS site, carrying the URI and call id, never data; each View re-reads as its viewer.
- **Sign-offs** (`sign_offs_api.py`, rules `sign_offs.py`): a site asks one person (`subject`) or an agent's admins to approve one action with a passkey. `return_url` must be https on an origin the site registered (422 `bad_return_url`); `approvers_for` picks the approver (a member of the site's workspace, or the workspace agent's owner/admins) else 422 `no_approver`; `may_approve` is asked again at every call and anyone else gets 404. Approve is a setting needing a browser, a person and a passkey step-up (a token is 403). A decided or expired request is 409 `closed`. The approval is a JWS the site reads with `GET /api/sites/sign-offs/{id}` (another site's id is 404); it never reaches the browser. In the site's frame (`/api/embed/sign-offs/…`) the frame's delegated token proves only the site, so approval is a WebAuthn assertion made over canopy's origin, and only the site that asked can frame its request.
- **Runner attestations** (`runner_attestations_api.py`): the runner's proof (`dpop` / `aws-iam`) is bound to the exact request through its `htu` (an origin the site registered ending in a sha256 of the request), single-use; every refusal is the one 401 `proof_refused`, so a caller learns nothing about which runners or keys exist.
